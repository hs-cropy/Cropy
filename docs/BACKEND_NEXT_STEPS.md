# 백엔드 통합 이후 실행 순서

기준: 2026-10-14. 라이브러리·모델·시드 데이터는 인터넷에 연결된 상태에서 미리 준비하고, 현장에서는 로컬 추론과 DB를 사용한다.

## 1. LLM 기반 코드의 develop 통합

#67은 develop에 반영됐지만, #68~#70은 선행 기능 브랜치로 병합되어 LLM 파일이 develop에 도달하지 않았다. 이 후속 변경은 검토한 #70 커밋 `96bd726b`의 입력 계약·수치 검증·timeout 및 템플릿 코드를 그대로 반영한다. `/ready`는 develop의 구현을 유지한다.

현재 LLM 함수는 서비스 단위이며 진단 API에서 호출하지 않는다. 실제 모델 호출 또는 Qwen/RKLLM 온디바이스 실행이 완료됐다는 의미는 아니다.

## 2. 온라인 사전 준비와 농약 카탈로그

**상태(2026-10-20): PSIS 키 발급 후 실제 동기화 완료.** 2026-10-20 동기화 기준으로 개발 PC에서 제품 23개, 작물·병해별 사용 조건 25개(무인항공 조건 제외 후)를 받았고, DB 반영 후 API에서 `verified`·`PSIS`로 제공되는 것을 확인했다. 개수는 동기화 시점의 PSIS 등록 현황에 따라 달라진다. 2026-10-26부터 이 동기화 결과 `backend/app/data/seed/pesticide_catalog.json`(`synced_at` 2026-10-20)을 저장소에 포함한다. 공개 등록 정보이며 API 키는 들어 있지 않다. 따라서 배포 서버·보드는 별도 동기화 없이 같은 검증 카탈로그를 쓰며, 카탈로그가 있으면 기존 시드(`legacy_unverified`)의 농약·연결은 모두 카탈로그로 교체된다(배추 검은썩음병은 PSIS 정확 일치 등록이 없어 0개). 인터넷을 연결하는 것만으로 자동 갱신되지는 않는다. 서버 실행 중 자동 동기화는 별도 작업으로 계획 중이다.

실제 PSIS 동작은 매뉴얼(v1.0)과 다르다. 스크립트는 확인한 동작에 맞춰져 있다.

- `startPoint`는 매뉴얼의 "페이지 번호"가 아니라 1부터 시작하는 **항목 위치**다(1, 51, 101…).
- `similarFlag=N`이어도 병해명이 부분 일치로 섞여 온다(예: `검은무늬병` → `세균검은무늬병`, `탄저병` → `전착효과(탄저병)`). 병해명이 정확히 같은 항목만 쓰고 나머지는 카탈로그 `queries[].excluded_disease_names`에 기록한다.
- 목록 응답에 매뉴얼에 없는 `buildTime`·`displayCount`·`startPoint`가 있다.
- 무인항공(드론) 살포 조건은 희석배수 대신 면적당 원액량(예: `100㎖/10a`)이라 일반 살포와 혼동될 수 있어 제외하고 `excluded_aerial_usages`에 개수를 남긴다.
- 배추 검은썩음병은 PSIS에 정확한 이름으로 등록된 농약이 없다(유사 검색 결과는 다른 병해). 사용 조건 0건으로 반영되며 다른 병해의 농약으로 채우지 않는다.
- 병해별 최대 5개 제품은 API 반환 순서(성분명 가나다순)로 고른다. 선택 기준은 팀에서 정한다.

1. 대상 장치의 OS·ARM64에 맞는 Python/torch/torchvision 의존성, 프론트 산출물 또는 컨테이너 이미지, 모델 파일과 시드를 온라인 상태에서 준비한다. PC 설치 성공을 ARM64 설치 성공으로 대체하지 않는다.
2. PSIS 키를 실행하는 셸의 환경 변수 `PSIS_API_KEY`로 설정한다. 키는 Git이나 실행 로그에 남기지 않는다. `backend/.env`에 넣으면 앱 설정 검증(`extra_forbidden`)으로 백엔드가 시작하지 않고 스크립트도 `.env`를 읽지 않는다. `--api-key` 인자는 셸 기록에 남으므로 쓰지 않는다. PowerShell 예: `$env:PSIS_API_KEY = Read-Host "PSIS API 키"`
3. 저장소의 `backend` 디렉터리에서 준비된 Python 환경으로 실행한다.

   ```bash
   python scripts/sync_pesticides.py
   ```

4. 생성된 `backend/app/data/seed/pesticide_catalog.json`의 `source`, `synced_at`, 조회 대상과 결과를 확인한다. 동기화 실패 시 기존 카탈로그를 유지하며, 미검증 데이터를 수동으로 `verified`로 바꾸지 않는다.
5. 기존 DB·업로드를 백업한 뒤 반영한다. 소스 직접 실행은 백엔드를 재시작한다. Docker는 시드가 이미지 안에 복사되므로 **카탈로그 생성 후 이미지를 다시 빌드하고 컨테이너를 재생성**해야 한다. 단순 `restart`로 호스트의 새 JSON이 복사되지는 않는다. 기존 데이터 볼륨을 삭제하지 않는다.
6. `/api/v1/ready`와 병해 상세의 `pesticides`를 확인한다. 유효한 사용 조건은 `verification_status=verified`, `source=PSIS`, `synced_at`과 함께 제공되는지 확인한다. 원본에 없는 안전 수치는 계속 `null`이어야 한다. 조회 결과가 없는 병해는 임의로 채우지 않는다.

현장 실행 시 PSIS를 매번 호출하지 않는다. 마지막으로 준비한 카탈로그를 사용하며 온라인 재갱신 일정은 별도로 정한다. 동기화 시각이 현재 등록·제품 표시사항의 정확성을 영구 보장하지는 않는다.

## 3. 로컬 Qwen/RKLLM 연결

**현재 대기 사유: Orange Pi와 로컬 LLM 실행 환경·API 계약 미준비.**

환경이 준비되면 로컬 주소, 요청/응답 형식, 모델 버전, 준비 상태 API, 동시 처리와 취소 지원을 먼저 확인한다. 이 계약을 기준으로 `generate_guidance()`의 비동기 caller를 구현하고 진단 결과→`build_llm_input()`→안내 응답을 API 및 화면·음성에 연결한다. 함수 토큰 방식과 자연어 직접 생성 방식 중 실제 서빙 방식도 ML 담당과 확정한다.

HTTP 클라이언트 자체 timeout, 요청 중복 처리, 취소, 제공자 실패 시 템플릿, 재촬영·낮은 신뢰도·Mock 상태 보존을 통합 검증한다. 제공자가 문자열을 반환한다고 내용이 검증된 것은 아니다. 농약 수치와 근거 없는 확진 표현은 출력·낭독 전에 별도 검증한다. 연결 전에는 템플릿 동작만 확인 가능하다.

## 4. 단말 배포와 인터넷 차단 검증

인프라 담당과 [이전 백로그](ORANGEPI5_MIGRATION_BACKLOG.md)의 OP-03/04/09/15를 수행한다. 실제 사진 진단·재촬영·이력·이미지 조회, 인터넷 단절 상태의 접근, 재부팅 후 자동 시작, DB/업로드 보존과 복원까지 확인한다. HTTP 200만으로 통과 처리하지 않는다.

PC에서 실제 CNN과 별도 SQLite를 사용하고 Python의 외부 DNS·소켓 연결을 차단한 검증은 성공했다. Windows 이벤트 루프의 loopback은 허용했다. 이는 보드 실행, 물리적 인터넷 단절, 브라우저 초기 설치/캐시, 실제 LLM 및 모델 정확도의 검증을 대체하지 않는다.

## 5. 운영 보관과 성능

[운영 안내](BACKEND_OPERATIONS.md)에 따라 DB·업로드·복구 초안을 함께 백업하고 대상 장치에서 복원을 연습한다. 저장 이력, 요청 캐시(`diagnosis_requests`), 만료 복구 초안의 보관 기간을 확정한 뒤 필요한 정리 작업을 구현한다. 보관 기간을 추측해 기존 자료를 자동 삭제하지 않는다.

CPU 추론의 초기 로드·예열 후 지연, 전체 스택의 p95·피크 RAM·온도와 장시간 운용을 측정한다. CPU가 목표를 충족하면 유지하고, 부족할 때 ONNX/RKNN 등의 변경을 검토한다.

## 판별 불가 결과의 LLM 입력 및 안내 처리

DiagnosisLLMInput의 severity는 필수 필드이며 null을 허용한다.
판별 불가(category="other") 결과의 severity=null을 그대로 보존한다.

다음 조건 중 하나에 해당하면 외부 LLM caller를 호출하지 않고
재촬영 안내 템플릿을 반환한다.

- category="other"
- decision_status="not_crop"
- decision_reasons에 "not_crop" 포함

응답은 source="template", fallback_reason="not_crop"이다.
not_crop은 제공자 장애가 아니라 판별 불가에 따른 의도적인 호출 생략이다.

템플릿은 기존 management_actions를 재촬영 방법으로 표시한다.
해당 목록이 없으면 기본 촬영 방법을 안내한다.
병해 설명과 예방 안내는 덧붙이지 않는다.
입력 수치 재검증은 호출 생략 여부를 판단하기 전에 수행한다.

이 변경은 LLM 서비스 단위의 처리이며, 진단 API에 실제 LLM 호출을
연결하거나 온디바이스 모델을 실행한 것은 아니다.

검증: Windows 로컬 관련 테스트 108 passed,
전체 백엔드 테스트 460 passed, 24 skipped, 1 warning.
