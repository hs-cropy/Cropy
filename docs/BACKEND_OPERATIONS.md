# 백엔드 운영 및 복구

## 실행 모드

개발 환경은 `APP_ENV=development`, `ALLOW_MOCK_PREDICTIONS=true`일 때 모델이 없어도 예시 진단을 제공한다. 응답과 화면에 mock임을 표시한다. 운영에서는 `APP_ENV=production`, `ALLOW_MOCK_PREDICTIONS=false`로 실행한다. Compose 기본값은 운영 모드다. 모델이 없거나 클래스 매핑이 잘못되면 진단을 503으로 차단한다.

`GET /api/v1/health`는 프로세스 생존 확인이다. `GET /api/v1/ready`가 200이어야 실제 모델과 DB 클래스 매핑이 준비된 상태다. 개발 mock은 ready가 503이다. pair 모델은 `ENABLE_PAIR_MODEL=true`로 명시적으로 켤 때만 사용한다. `MAX_CONCURRENT_DIAGNOSES` 기본값은 1이며 프로세스별 제한이다.

## DB 변경과 복구

기존 SQLite DB에 칼럼을 추가하기 전에 외래 키 무결성을 검사하고, 같은 디렉터리에 `.backup-UTC-고유값` 백업을 생성한다. 변경은 트랜잭션으로 처리한다. 외래 키 오류는 데이터를 임의 삭제하지 않고 기동을 중단하므로 원인을 확인한다. 백업을 만들 디스크 공간과 쓰기 권한이 필요하다.

수동 복구 시 서비스를 정지하고 현재 DB 및 업로드 디렉터리를 별도로 보존한다. 백업의 무결성을 검사한 뒤 백업을 설정된 DB 경로로 복사하고, 해당 백업과 호환되는 코드로 시작한다. SQLite WAL 사용 시 서비스 정지와 checkpoint를 확인하고 DB 파일만 운영 중 복사하지 않는다. 복구 후 이력과 이미지, readiness를 점검한다. 실제 복구 리허설은 대상 운영 장치에서 별도로 수행한다.

## 농약 카탈로그

기존 시드의 작물별 검증이 없는 사용량·희석비·안전기간은 API에서 숨긴다. PSIS 키를 환경 변수 `PSIS_API_KEY`로 설정한 뒤 backend 디렉터리에서 `python scripts/sync_pesticides.py`를 실행한다. 키를 로그나 저장소에 남기지 않는다.

성공하면 `app/data/seed/pesticide_catalog.json`에 제품과 작물·병해별 사용 조건을 함께 저장한다. 실제 경로는 스크립트의 `SEED_DIR` 또는 `--output`을 확인한다. 업무 오류, 일부 페이지 누락, 중복 식별자 등은 전체 갱신을 실패시켜 이전 파일을 보존한다. 백엔드를 재시작하면 검증된 전체 스냅샷을 트랜잭션으로 DB에 반영한다. 최신 등록·라벨 확인을 대체하지 않으며, 이번 코드 수정 과정에서 실제 PSIS 동기화는 실행하지 않았다.

## 업로드 정리

진단 실패 시 새 파일을 제거하고, 재촬영 저장이 성공하면 이전 재촬영 파일을 제거한다. 장애로 남은 고아 파일은 backend 디렉터리에서 아래 명령으로 먼저 확인한다.

```text
python scripts/cleanup_uploads.py --min-age-hours 72
```

목록 확인 후 서비스를 정지한 유지보수 시간에 동일 명령에 `--apply`를 붙이면 삭제한다. 기본은 미리보기이며 24시간보다 오래된 파일만 후보로 삼는다. DB가 참조하는 원본·재촬영 파일, 하위 폴더, 심볼릭 링크는 제외한다. 이 도구는 이력 보관기간 정책을 대신하지 않는다.

## 요청 제한

전체 HTTP 본문은 multipart 해석 전에 파일 제한 + 64 KiB로 제한한다. 작은 본문은 메모리, 큰 본문은 임시 디스크에 보관하므로 임시 공간을 확보한다. 이미지 디코딩은 별도 스레드에서 실행하며 픽셀 수도 제한한다. 느린 업로드 타임아웃과 외부 접속 제어는 배포 프록시 설정으로 관리한다.
