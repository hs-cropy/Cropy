## 클래스 정의

클래스 폴더명 앞 숫자가 `model_class_id`이고, 이 값이 DB `diseases.model_class_id`와
조인 키로 쓰인다. ImageFolder 정렬 인덱스에 의존하지 않으므로 클래스를 추가해도
기존 ID가 밀리지 않는다.

| id | 폴더명 | 작물 | 종류 |
|----|--------|------|------|
| 0 | `0_고추탄저병` | 고추 | 병해 |
| 1 | `1_고추흰가루병` | 고추 | 병해 |
| 2 | `2_무검은무늬병` | 무 | 병해 |
| 3 | `3_무노균병` | 무 | 병해 |
| 4 | `4_배추검은썩음병` | 배추 | 병해 |
| 5 | `5_배추노균병` | 배추 | 병해 |
| 6 | `6_고추정상` | 고추 | 정상 |
| 7 | `7_무정상` | 무 | 정상 |
| 8 | `8_배추정상` | 배추 | 정상 |
| 9 | `9_기타` | — | 판별 불가 (2026-10 추가) |

`9_기타`는 작물 잎이 아닌 사진(손·물건·배경 등)과 흐리거나 멀리서 찍어 잎을 알아볼 수 없는 사진을 받는 클래스다.
DB 이름은 "판별 불가"(category `other`, 농약 없음)이고, 판단 정책 `decision-v2`에서 `not_crop`으로 다른 판단 이유(작물 불일치·혼동·낮은 신뢰도)보다 우선한다.
백엔드는 9클래스·10클래스 체크포인트를 모두 받으므로 코드 배포와 모델 교체 순서가 무관하다.

10클래스 모델(`cropy_runs/full512_resnet50_other10_v1`, epoch 7, 입력 256): val 정확도 99.57%, Macro F1 0.958, 작물 사진 → 기타 1/4,070.
흐림 평가(검증 사진 합성 열화)에서 가우시안 σ2까지 작물 → 기타 0.34%, 같은 조건 9클래스 모델 정확도 77.8% 대비 새 모델 98.8%.
σ4·흔들림·저해상도처럼 잎을 알아보기 어려운 사진은 24~74%가 기타로 가며, 이때 9클래스 모델도 정확도가 25~70%로 무너진다.

## 기존 기본 모델의 학습 데이터

**AI Hub「노지 작물 질병 진단」**(073) 원천데이터. 파일명에 인코딩된 작물·병해 코드를
`ml/prepare_dataset.py`가 파싱해 ImageFolder 구조로 분할한다.

```
V006_79_{type}_{disease:02d}_{crop:02d}_{area:02d}_{grow:02d}_{risk}_...
```

병해는 `disease` 코드로, 정상(`type=0`)은 `crop` 코드로 분류한다.
클래스 균형을 위해 정상 클래스는 클래스당 200장(`--normal-cap`)으로 제한한다.

무노균병(3)은 원천 데이터 자체가 적어 다른 클래스의 절반이다. 이 불균형이
아래 성능 분석의 배경이 된다. `train.py --balanced-sampler`로 역빈도 가중
샘플링을 걸 수 있다.

**Augmentation (train):** RandomResizedCrop(scale 0.7~1.0), HorizontalFlip,
Rotation(±15°), ColorJitter(brightness/contrast 0.3, saturation 0.2)
**Loss/Optim:** CrossEntropy(label_smoothing=0.1), AdamW(wd=1e-4), CosineAnnealingLR

## 추론 파이프라인

1. 이미지 로드 (PIL, RGB 변환)
2. Resize → ToTensor → Normalize (ImageNet mean/std)
3. Model forward → softmax
4. `(model_class_id, confidence)` 전체 분포를 내림차순 정렬
5. 응답에는 상위 3개, 다시점 융합에는 전체 분포를 사용
6. `model_class_id` → DB `diseases` 조인

추론 해상도는 체크포인트의 `img_size` 필드를 따르며, 필드가 없는 구버전
체크포인트는 224로 폴백한다. **현재 로컬 기본 경로의 `best_model.pth`에는 이 필드가 없다**
(아래 [알려진 이슈](#알려진-이슈) 참고).

## 작업자 분리 시험셋과 기준선 (2026-10-28)

위 수치와 10클래스 모델의 val 99.6%는 모두 **학습에 쓴 촬영 작업자와 같은 작업자의 사진**으로 잰 값이다.
AI Hub 공식 Validation 4,070장 중 4,063장이 Training과 같은 작업자·같은 날짜 묶음이고, 작업자 기준으로는 전부 겹친다.
그래서 새 사용자가 찍은 사진의 성능을 말해 주지 못한다.

**분할.** 파일명의 작업자 코드(날짜 앞 토큰) 78명을 통째로 train/val/test에 배정했다(`ml/plan_worker_split.py`, 배정표 `ml/worker_split_v1/workers.json`, seed 1568).
클래스마다 시험 작업자 2명 이상, 검증 1명 이상을 두고 70/10/20에 가깝게 맞췄다. 같은 바이트의 사진이 분할을 넘는 경우는 없다.
9_기타의 AI Hub 조각은 원본 사진의 작업자를 따르고, COCO 조각은 내용 해시로 70/10/20 나눈다.

시험 11,434장 기준이며, 서버 모델 열은 이 작업자들을 학습했으므로 격차를 보여 주는 참고값이다.

- 무검은무늬병 212장 중 77장이 무노균병으로 갔다. 무 질병 작업자별 정확도는 2852e 57%, 5389e 63%이고 다른 작물 작업자는 94~97%다.
- 고추탄저병 361장 중 20장이 고추정상으로 갔다.
- 검증 macro F1은 epoch 1~8에서 0.83~0.88로 거의 평평했다. epoch를 늘려도 이득이 없다.

**앞으로의 판정 기준.** 모델 변경(백본·증강·해상도·데이터 추가)은 이 시험셋의 macro F1 0.899, 무검은무늬병 53.8%, 무노균병 74.4%와 비교한다.
무 시험 사진은 작업자 2명뿐이라 몇 %p 차이는 의미가 없고, 10%p 이상 움직여야 개선으로 본다. 채택한 방법의 최종 모델은 전체 데이터로 다시 학습한다.

**한계.**
- 작업자 분리는 농장·지역 분리가 아니다. 라벨의 `region`은 무 질병 전부 9, 배추 질병 전부 1이고 고추는 7·8을 모든 작업자가 함께 찍었다. 다른 지역 밭의 성능은 이 자료로 잴 수 없다.
- 시험 작업자의 촬영 날짜 상당수가 학습 작업자와 겹친다(무노균병 9일 중 5일). 같은 밭을 여러 명이 찍었을 수 있어 시험 점수도 낙관적일 수 있다.
- 질병 사진과 정상 사진의 작업자가 전혀 겹치지 않는다. 촬영 스타일로 정상/질병을 구분하는 교란은 이 시험셋으로 잡히지 않는다.
- AI Hub 147의 질병 원본은 이미 전부 보유하고 있고(공식 수량은 증강본 포함), 국내 밭에서 찍은 무·배추·고추 병해 공개 데이터는 달리 없다. 위 한계를 넘으려면 다른 지역·다른 촬영자의 밭 사진을 직접 모아야 한다.

### 실험 1: 백본 교체 ConvNeXt-Tiny (2026-10-28) — 기각

같은 분할·같은 설정에서 백본만 torchvision ConvNeXt-Tiny(ImageNet 가중치)로 바꿔 8 epoch 학습했다(`ml/cropy_testset_convnext_colab.ipynb`, Drive `cropy_testset/convnext_v1/`, 리포트 `ml/worker_split_v1/convnext_v1_test_report.json`). 선택 epoch 6.

| 시험셋 지표 | 기준선 ResNet50 | ConvNeXt-Tiny |
|---|---:|---:|
| 전체 정확도 | 98.0% | 98.2% |
| macro F1 | 0.899 | 0.905 |
| 2 무검은무늬병 recall | 53.8% | 52.4% |
| 3 무노균병 recall | 74.4% | 80.8% |
| 0 고추탄저병 recall | 93.4% | 94.5% |
| 1 고추흰가루병 recall | 97.9% | 95.8% |
| 무 작업자 정확도 (2852e / 5389e) | 57% / 63% | 65% / 60% |

- 무검은무늬병 212장 중 무노균병으로 간 사진이 77장 → 83장으로 오히려 늘었다. 무 두 질병의 혼동은 백본 용량 문제가 아니다.
- 무노균병 +6.4%p, macro F1 +0.006은 판정 기준(10%p)에 못 미치고, 작업자 2명 규모에서는 잡음 범위다.
- 검증 무검은무늬병 recall도 25%→22%로 같은 경향이다.
- 결론: 백본 교체는 채택하지 않는다. 서버 모델은 ResNet50을 유지한다. 다음 실험은 무 질병 두 클래스의 혼동을 직접 겨냥한 것(판별 부위 crop·고해상도 입력·무 전용 데이터 추가)이어야 한다.

### 실험 2: 입력 해상도 256→448px (2026-10-30) — 부분 개선, 후보 채택

같은 분할·같은 설정(ResNet50)에서 입력 크기만 448px로 올려 8 epoch 학습했다(`ml/cropy_testset_hires448_colab.ipynb`, Drive `cropy_testset/hires448_v1/`, 리포트 `ml/worker_split_v1/hires448_v1_test_report.json`). 원본이 512px이라 448은 병반 질감을 거의 그대로 쓴다. 선택 epoch 4, T4에서 epoch당 약 24분.

| 시험셋 지표 | 기준선 256px | 448px |
|---|---:|---:|
| 전체 정확도 | 98.0% | 98.7% |
| macro F1 | 0.899 | **0.917** |
| 2 무검은무늬병 recall | 53.8% | 54.2% |
| 3 무노균병 recall | 74.4% | **88.5%** |
| 0 고추탄저병 recall | 93.4% | 94.7% |
| 4 배추검은썩음병 / 5 배추노균병 | 95.7% / 96.0% | 97.0% / 98.4% |
| 6~8 정상, 9 기타 | 99.2~99.7% | 99.9~100% |
| 무 작업자 정확도 (2852e / 5389e) | 57% / 63% | 69% / 63% |

- 무노균병 +14.1%p는 판정 기준(10%p)을 넘는다. 무노균병 78장 중 무검은무늬병으로 간 사진이 16장 → 8장으로 줄었다. 검증에서도 71%→86%로 같은 방향이다.
- 무검은무늬병은 그대로다. 212장 중 85장이 여전히 무노균병으로 간다. 해상도는 노균병 쪽 병반(흰 곰팡이·황화)을 살려 주지만, 검은무늬병을 노균병으로 보는 쪽 혼동은 줄이지 못한다.
- 정상·기타·배추 클래스는 전부 소폭 상승했고 나빠진 클래스는 없다.
- 결론: 448px는 채택 후보다. 다만 추론 연산량이 약 3배이므로 서버 교체 전에 (1) 전체 데이터(공식 train+val)로 448px 재학습, (2) 서버 CPU/GPU에서 1장당 추론 시간 측정이 필요하다. 무검은무늬병은 별도 대책(무 질병 전용 2단계 분류기 또는 데이터 추가)이 여전히 필요하다.
- 교체 준비 상태(2026-10-30): 백엔드 `ml_service.py`는 체크포인트의 `arch`·`img_size`를 읽어 전처리하므로 코드 수정 없이 448px 체크포인트를 쓸 수 있다. CPU 추론(ResNet50, 배치 1, 22스레드 노트북 기준) 256px 78ms → 448px 185ms. 전체 데이터(공식 train 37,753 / val 4,635, 10클래스) 448px 재학습 노트북은 `ml/cropy_full448_colab.ipynb`(Drive `cropy_testset/full448_v1/`)이며, 결과가 나오면 공식 val 회귀 확인 후 `docs/operations/MODEL_SWAP_10CLASS.md` 절차로 교체한다.
- 전체 데이터 448px 재학습 결과(2026-11-02, 8 epoch 중 6 선택, `ml/worker_split_v1/full448_v1_val_report.json`): 공식 val 4,635장 99.68% / Macro F1 0.962(현재 서버 모델 99.57% / 0.958), 작물→판별 불가 0장(현재 1장), 무검은무늬병 71/76(현재 70), 무노균병 16/24(현재 17), 배추검은썩음병 110/110(현재 108). 회귀 없음으로 보고 교체 인계 문서 `docs/operations/MODEL_SWAP_448.md`를 작성했다. 파일 `full512_resnet50_448_other10_v1.pth`, SHA256 `274527c5742da193fc0e9b1eda60744c94fb758210823e56175b7e8e957e45e7`.

### 실험 3: 무 질병 전용 2단계 분류기 (2026-11-02) — 기각

448px 본 모델의 무검은무늬병→무노균병 혼동(212장 중 85장)을 겨냥해, 작업자 분할의 학습 사진(무검은무늬병 267장 + 무노균병 124장)으로 2클래스 전용 분류기(ResNet50, 448px, 12 epoch 중 11 선택)를 학습하고 시험 작업자의 무 질병 290장으로 비교했다(`ml/cropy_testset_pair_colab.ipynb`, 리포트 `ml/worker_split_v1/pair_v1_test_report.json`, Drive `cropy_testset/pair_v1/`). PR #112의 공정 비교(256px 본 모델, 촬영지·날짜 묶음 제외)와 같은 질문을 작업자 분리 시험셋에서 다시 물은 것이다.

| 무 질병 290장 | 본 모델 448px | 전용 분류기 단독 | 본 + 전용(백엔드 재분배 규칙) |
|---|---:|---:|---:|
| 정확도 | 63.4% | 65.9% | 60.0% |
| 무검은무늬병 recall (212) | 54.2% | 59.9% | 52.4% |
| 무노균병 recall (78) | 88.5% | 82.1% | 80.8% |
| 균형 정확도 | 71.3% | 71.0% | 66.6% |
| McNemar vs 본 모델 | — | 31 vs 38, p=0.47 | 27 vs 17, p=0.17 |

- 전용 분류기 단독은 본 모델과 차이가 없고(p=0.47), 백엔드 재분배 규칙으로 합치면 오히려 나빠진다(게이트가 열린 157장 모두 무 질병 사진이었고 다른 클래스에는 영향 없음). PR #112와 같은 결론이다.
- 갈리는 지점은 피해 정도다. 전용 분류기는 **심한 검은무늬병**(risk 2: 15→23/27, risk 3: 5→14/17)은 훨씬 잘 맞히지만 **가벼운 검은무늬병**(risk 1: 95→90/168)과 노균병(69→64/78)을 더 틀린다. 두 모델이 서로 다른 사진을 맞히는데, 합산 규칙은 그 장점을 살리지 못한다.
- 본 모델의 무검은무늬병 오류는 촬영일 11월 10일 이후(85장 중 57장 오답, 정답률 33%)와 피해 정도 2·3(44장 중 24장 오답)에 몰려 있다. 학습 데이터의 무검은무늬병은 피해 정도 2가 6장, 3이 0장뿐이다. 시험셋의 무노균병 사진은 전부 11월 10일 이전이라, 모델이 늦가을 잎 상태를 노균병 단서로 쓰고 있을 가능성이 크다.
- 결론: 전용 분류기는 채택하지 않고 `ENABLE_PAIR_MODEL=false`를 유지한다. 무검은무늬병 문제는 백본·해상도·2단계 구조로는 풀리지 않는 **데이터 문제**다. 다음 수단은 (1) 피해가 심한 검은무늬병과 11월 중·하순 무 잎 사진을 직접 수집해 학습에 넣는 것, (2) 그 전까지는 무 질병 두 후보가 근접할 때 유도촬영으로 재촬영을 요구하는 현재 흐름을 유지하는 것이다.

### 실험 4: 병반 박스 crop (2026-11-02) — 배경 단서 가설 기각

AI Hub 라벨 JSON의 병반 박스(`annotations.points`, 원본 좌표)를 512px 묶음 좌표로 축소해 질병 사진만 박스 주변(각 변 15% 여유)으로 잘라 낸 데이터셋을 만들고, 같은 작업자 분할·같은 설정(ResNet50, 448px, 8 epoch)으로 학습했다(`ml/cropy_testset_boxcrop_colab.ipynb`, Drive `cropy_testset/boxcrop_v1/`, 리포트 `ml/worker_split_v1/boxcrop_v1_test_report.json`). 박스는 질병 사진 4,301장 중 4,258장에 있었고(43장은 라벨의 원본 크기가 0이라 제외), 박스가 사진에서 차지하는 비율은 중앙값 52%(10분위 18%, 90분위 97%)다. 정상·기타 사진은 박스가 없어 그대로 두었다.

가설은 "본 모델이 병반이 아니라 배경·계절 단서로 무 질병을 가른다"였다. 시험셋 무 질병 290장에서:

| 학습 → 평가 | 무검은무늬병 recall | 무노균병 recall | 균형 정확도 |
|---|---:|---:|---:|
| 전체 사진 → 전체 사진 (기존 448px) | 54.2% | 88.5% | 71.4% |
| 전체 사진 → 박스 crop | 58.0% | 73.1% | 65.6% |
| 박스 crop → 박스 crop | 65.6% | 69.2% | 67.4% |
| 박스 crop → 전체 사진 | 40.1% | 29.5% | 34.8% |

- 병반만 보고 배워서 병반만 보고 판정해도(3행) 무검은무늬병 212장 중 63장이 여전히 무노균병으로 가고, 무노균병은 오히려 23장이 검은무늬병으로 간다. 균형 정확도는 기존 모델보다 낮다. **배경을 치워도 두 무 질병의 혼동은 그대로다.** 이 해상도(512px 묶음에서 잘라 낸 병반)에서는 병반 자체가 두 병을 가르지 못한다.
- 기존 모델을 박스 crop에 평가하면(2행) 무노균병이 15%p 떨어진다. 본 모델이 노균병 판정에 잎 전체 맥락(황화 범위 등)을 쓰고 있고, 그것이 틀린 단서라고 볼 근거는 없다.
- 설계상 한계: 정상·기타는 자르지 않아 "잘린 구도 = 질병"이 새는 단서가 됐다. 3행의 고추 질병 99.7%와 4행의 붕괴(고추 질병 361장 중 216장이 고추정상)는 그 때문이며, crop 학습 모델은 첫 사진용 후보가 아니다. 무 질병 두 클래스는 둘 다 잘라 냈으므로 두 클래스 사이의 비교는 유효하다.
- 결론: 배경 단서 가설은 기각한다. 남는 설명은 (1) 512px 묶음 해상도에서 두 병의 병반 질감이 구분되지 않거나, (2) 11월 중순 이후·피해가 심한 검은무늬병 사진에 실제로 노균병이 함께 있거나 라벨이 흔들린다는 것이다. 다음 단계는 오분류 사진을 직접 눈으로 확인하는 것(contact sheet)과, 그 결과에 따라 AI Hub 원본 해상도 병반 crop 또는 라벨 재검토다.
- 육안 확인(2026-11-02, Drive `cropy_testset/boxcrop_v1/contact_*.jpg`): 노균병으로 간 검은무늬병 89장은 대부분 **지름 몇 mm의 옅은 회백색 반점에 갈색 테두리**가 몇 개 있는 잎이고, 11월 중순 이후 사진은 잎 가장자리 황화와 검은 괴사 반점이 섞여 있다. 그런데 **정답으로 맞힌 노균병 30장도 같은 양상**(옅은 회백색 반점 + 갈색 테두리)이고, 정답으로 맞힌 검은무늬병 30장은 아주 작은 검은 점이 흩어진 잎이다. 즉 이 데이터셋에서 "노균병" 라벨과 틀린 "검은무늬병" 라벨은 겉보기가 같다. 512px 묶음에서는 반점이 10px 안팎이라 윤문(동심원) 같은 세부 구조도 보이지 않는다.
- 따라서 무 두 질병의 혼동은 (1) 라벨 기준이 작업자·시기에 따라 흔들렸거나 같은 잎에 두 병이 섞여 있고, (2) 현재 해상도에서 판별 세부가 사라진 결과로 본다. 모델 쪽에서 남은 수단은 AI Hub 원본 해상도(5472×3648)에서 병반을 잘라 세부 구조로 학습하는 것뿐이며, 서비스 쪽은 무 질병 두 후보가 근접할 때 잎 뒷면 근접 재촬영을 요구하는 현재 흐름이 맞다(노균병의 흰 곰팡이는 뒷면에서 확인된다).

### 실험 5: 원본 해상도 병반 crop (2026-11-02) — crop 품질은 효과 있음, 재현 필요

AI Hub 원본(5472×3648) 무 질병 사진에서 같은 박스를 잘라 긴 변 1024px로 저장한 crop(`ml/make_radish_hires_crops.py`, 746장, 원본 crop 긴 변 중앙값 3,024px; 라벨 원본 크기가 0인 43장 제외)과, 512px 묶음에서 자른 crop(긴 변 약 300px)으로 **무 질병 전용 분류기를 같은 사진·같은 작업자 분할·같은 설정(ResNet50, 12 epoch)** 으로 학습해 비교했다(`ml/cropy_testset_hirescrop_colab.ipynb`, 리포트 `ml/worker_split_v1/hirescrop_v1_test_report.json`, Drive `cropy_testset/hirescrop_v1/`). 학습 391장, 검증 65장, 시험 290장(작업자 2852e·5389e).

| 모델 | crop 원본 | 입력 | 정확도 | 무검은무늬병 recall | 무노균병 recall | 균형 정확도 |
|---|---|---:|---:|---:|---:|---:|
| `low448` | 512 묶음 crop | 448 | 54.5% | 43.4% | 84.6% | 64.0% |
| `hi448` | 원본 crop | 448 | **70.3%** | **65.6%** | 83.3% | **74.4%** |
| `hi768` | 원본 crop | 768 | 57.9% | 51.4% | 75.6% | 63.5% |

- `hi448` vs `low448`: 같은 사진 290장에서 hi만 맞힌 56장, low만 맞힌 10장(McNemar p<0.001). **crop 품질(리샘플링 손실)이 무 질병 구분에 영향을 준다.** 피해 정도별로도 전부 올랐다(risk 1: 75→108/168, risk 2: 13→20/27, risk 3: 4→11/17).
- `hi768`은 `hi448`보다 나쁘다(hi448만 맞힘 49장, hi768만 13장). 사진 391장으로 768 입력을 12 epoch 돌린 단일 실행이라 학습 불안정으로 본다. 입력 해상도 효과는 이 실험으로 판단할 수 없다.
- 한계: 세 모델 모두 seed 1회이고 검증이 65장이라 epoch 선택이 흔들린다(hi448은 5 epoch, hi768은 10 epoch 선택). `hi768`의 역전이 그 증거다. **채택 전에 seed 3회 반복으로 `hi448 > low448`이 유지되는지 확인해야 한다.**
- 본 모델(448px, 전체 사진)의 같은 290장 성적은 정확도 63.4%, 균형 71.4%였다. `hi448`은 정확도 +7%p, 균형 +3%p로, 전체 사진 모델보다 조금 낫지만 압도적이지 않다. 라벨이 흔들리는 사진(실험 4 육안 확인)은 어느 쪽도 못 맞힌다.
- (2026-11-02 추가) 실험 6의 seed 반복에서 이 효과는 재현되지 않았다. 아래 실험 6 참조.

### 실험 6: 실험 5의 seed 반복 (2026-11-02) — 재현 실패, crop 품질 효과 기각

실험 5의 `low448`·`hi448`을 seed 1·2·3으로 같은 설정에서 다시 학습했다(`ml/cropy_testset_hirescrop_seeds_colab.ipynb`, 학습 스크립트 `ml/train_full_colab_seed.py`(`--seed` 추가), 리포트 `ml/worker_split_v1/hirescrop_seeds_v1_test_report.json`, Drive `cropy_testset/hirescrop_seeds_v1/`).

| seed | `low448` 정확도 / 균형 | `hi448` 정확도 / 균형 | McNemar (low만 / hi만 맞힘) |
|---:|---:|---:|---|
| 1 | 57.6% / 66.5% | 65.2% / 69.3% | 21 / 43, p=0.008 (hi 우세) |

| 평균±표준편차 | 61.4±3.4% / 68.9±1.7% | 63.7±8.4% / 68.3±3.1% | |

- seed 2개에서는 `hi448`이, 1개에서는 `low448`이 유의하게 좋았다. 균형 정확도 평균은 같고(68.9% vs 68.3%), `hi448`의 편차가 2배 이상 크다. **원본 해상도 crop 효과는 재현되지 않는다.** 실험 5의 +16%p는 seed와 epoch 선택(검증 65장)의 운이었다.
- 무검은무늬병 recall은 `hi448`에서 seed에 따라 39.6%~75.0%까지 흔들린다. 학습 391장·검증 65장 규모에서는 어떤 비교도 seed 잡음이 효과를 덮는다. 실험 5의 "768 입력이 더 나쁘다"도 같은 잡음이었다고 본다.
- 결론: 모델·해상도·crop 쪽 실험은 여기서 멈춘다. 무 두 질병의 혼동은 (1) 라벨이 흔들리는 사진(실험 4 육안 확인), (2) 학습 사진 391장이라는 규모 한계에 묶여 있고, 둘 다 데이터 수집과 라벨 재검토로만 풀린다. 서비스 쪽 결론은 변하지 않는다: 448px 본 모델 교체 + 무 질병 근접 재촬영 유도 유지, 전용 분류기는 `ENABLE_PAIR_MODEL=false` 유지.

## 혼동쌍 유도촬영

`backend/app/services/recapture.py` 구현.

### 1) 혼동 판정

1차 진단의 상위 두 후보가 사전 정의된 혼동쌍이고, 신뢰도 마진(1위 − 2위)이
**0.20 미만**이면 재촬영을 유도한다.

| 혼동쌍 | 판별부위 | 판별 단서 |
|--------|----------|-----------|
| 2 무검은무늬병 ↔ 3 무노균병 | 잎 뒷면 | 뒷면 회백색 포자층 → 노균병 / 뒷면 깨끗 + 앞면 동심원 병반 → 검은무늬병 |
| 4 배추검은썩음병 ↔ 5 배추노균병 | 잎맥·잎 가장자리 | 잎맥 흑변 + V자 황변 → 검은썩음병 / 뒷면 회백색 포자 + 각진 반점 → 노균병 |

> 병리 단서는 표준 병징에 근거하나, 배포 전 식물병리 자료로 검증이 필요하다.

### 2) 다시점 융합

2차 사진을 받으면 1차·2차의 **전체 분포**를 가중 평균한다.
2차는 판별부위를 표적 촬영한 것이므로 가중을 크게 준다.

```
fused[c] = 0.4 · dist1[c] + 0.6 · dist2[c]
```

### 3) 혼동쌍 전용 분류기

`pair_mu.pth`(ResNet18, 2-class)가 있으면 그 쌍이 차지한 **합계 질량은 보존한 채
내부 비중만** 전문가 확률로 재분배한다. 쌍 밖 클래스는 영향받지 않는다.

```
combined = fused[a] + fused[b]
fused[a] = combined · spec[a] / (spec[a] + spec[b])
```

적용 조건: 전문가 분류기가 학습한 두 클래스가 **1차 진단의 상위 두 후보와 일치**할 때만.
이 게이트가 없으면 무 전용 분류기가 배추 혼동쌍 재촬영에도 적용되어 무 후보의
순위가 근거 없이 뒤집힌다.

## 알려진 이슈

**1. 혼동쌍 전용 분류기가 아직 이득을 주지 못한다**

`pair_mu.pth`의 자체 test 성능은 **76.1%**(113장; 검은무늬병 84.0% / 노균병 60.5%)다.
같은 쌍에 대한 9-class 본 모델의 쌍 내부 판별력은 78/104 = **75.0%**로 사실상 차이가 없다
(단, 두 수치는 서로 다른 분할에서 나온 값이라 직접 비교는 아니다).

원인으로 의심되는 지점: `prepare_pair.py`는 AI Hub 원천에서 **병해 코드로만** 이미지를
모은다. 즉 전용 분류기의 학습 데이터도 본 모델과 같은 일반 촬영 사진이며,
정작 판정 대상인 **잎 뒷면 근접 사진으로 학습된 적이 없다.** 학습·서빙 도메인이
어긋나 있어, 판별부위 이미지가 포함된 데이터 확보가 선행되어야 한다.

**2. 체크포인트에 `img_size` 메타데이터가 없다**

현재 로컬 기본 파일 `best_model.pth`는 `img_size` 필드 없이 저장돼 추론·평가가 모두 224로 폴백한다.
해상도별 val 정확도를 실측한 결과 **224px 94.7% / 256px 94.5% / 288px 95.3%**로,
224 폴백이 유의미한 손실을 내고 있지는 않다 (288의 +0.6%p는 4장 차이).
다만 학습 해상도를 체크포인트만으로 재현할 수 없다는 문제는 남으므로,
재학습 시 `train.py`가 기록하는 `img_size`를 유지해야 한다.

**3. 무노균병 데이터 부족**

학습 175장으로 다른 클래스의 절반이다. `--balanced-sampler`와 추가 데이터 확보가
2·3 혼동 완화의 가장 직접적인 수단이다.

## 최신 학습과 최적화 상태

전체 데이터 학습은 `train_full_colab.py`와 `cropy_full_colab.ipynb`를 사용한다. 입력 256, 클래스 균형 샘플링, AdamW, weight decay 1e-4, label smoothing 0.1, seed 42이며 검증 Macro F1으로 모델을 선택한다. 256/384 미세조정은 동일 시작 가중치에서 lr 1e-5, batch 16, 추가 5에폭을 비교했다. 일반 `train.py`의 검증 정확도 선택과 구분한다.

브라우저용 FP32 ONNX 변환과 ONNX Runtime Web/WASM 추론은 구현되어 있다. [오프라인 가이드](OFFLINE_WEB.md)에 동일 입력 텐서의 PyTorch/ONNX 비교와 Chrome 연결 차단·재접속 검증 기록이 있다. 이는 사진별 전처리 동등성이나 병해 정확도 검증을 뜻하지 않으며 이번 문서 수정에서 재실행하지 않았다. RKNN 변환·INT8 정확도·실제 휴대폰 및 보드 지연/메모리/전력은 미검증이다. [양자화 계획](QUANTIZATION.md)의 크기·속도는 목표와 비교 방법으로 관리한다.

Qwen3.5 기능 선택·한국어 안내는 추가 개발 대상이다. 7기능 싱글턴 초안 2,800개(train 2,240/validation 560)의 v6 AI 검수는 문제 미발견 2,239/보류 397/불합격 164이며 사람 승인 0개다. 자연어 설명만 생성하는 초기 계획과 기능 토큰 데이터 버전을 구분한다. tokenizer 실제 ID·종료·handler·TTS·학습·RKLLM 보드 추론은 미검증이다.
