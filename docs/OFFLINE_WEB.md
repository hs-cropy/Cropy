# Cropy 오프라인 실행과 검증

2026-10-08 구현. 사용자가 선택한 두 실행 방식 모두 제공한다. 기존 서버 진단은 유지하며, 브라우저 자체 추론은 상단 **기기 진단** 링크(`/offline/index.html`)에서 사용한다.

## 실행 방식

| 방식 | 사진 분석 | 기록 저장 | 인터넷 없이 필요한 연결 |
|---|---|---|---|
| Orange Pi 로컬 서버 | 기존 FastAPI/PyTorch 모델 | 보드의 SQLite와 업로드 폴더 | 휴대폰↔보드의 로컬 Wi-Fi/LAN 연결 |
| 스마트폰 브라우저 자체 실행 | ONNX Runtime Web, WASM CPU | 해당 브라우저·오리진의 IndexedDB | 준비 후 서버 연결도 필요 없음 |

브라우저 자체 실행은 처음에 페이지·약 94MB 모델·약 14MB WASM 런타임을 받아야 한다. 준비 파일은 인터넷이나 로컬 보드에서 받을 수 있다. 모델 SHA-256·파일 크기·세션 생성이 모두 성공한 뒤 저장된 모델을 교체한다. 중단·업데이트 실패 시 기존 모델을 유지한다. 다운로드 재개는 처음부터 다시 받는 방식이다.

Service Worker와 모델 준비에는 HTTPS가 필요하다. 개발용 localhost/127.0.0.1 예외와 달리 휴대폰에서 `http://보드IP:3000`으로 접속하면 자체 오프라인 준비는 지원하지 않는다. 이 주소의 기존 **서버 진단**은 계속 사용할 수 있다. 자체 실행을 제공할 때는 휴대폰이 신뢰하는 인증서와 HTTPS 프록시를 구성해야 한다. [MDN 보안 컨텍스트](https://developer.mozilla.org/en-US/docs/Web/Security/Defenses/Secure_Contexts)

## 모델 준비

모델 변환은 개발 PC에서 한다. backend의 기존 검증을 통과한 `ml/checkpoints/best_model.pth`가 필요하다. 체크포인트와 ONNX 파일은 대용량 산출물이므로 Git에 포함하지 않는다.

```powershell
cd backend
.venv/Scripts/python.exe -m pip install -r requirements-browser-export.txt
.venv/Scripts/python.exe scripts/export_browser_model.py
cd ../frontend
npm ci
npm run build
```

생성물은 `frontend/public/offline-assets/`의 `cnn-<hash>.onnx`, `manifest.json`, `manifest-<bundle version>.json`이다. 묶음 버전은 모델·전처리·병해 안내·판단 기준을 포함한다. 이전 manifest 아카이브는 이전 기기 기록 동기화에 필요하므로 유지한다. ONNX 모델의 hash와 묶음 버전은 서로 다르다. JS/WASM은 빌드 시 같은 npm 패키지에서 `public/offline-runtime/`으로 복사하고 앱 파일 hash에 따라 Service Worker 캐시 이름을 갱신한다. 외부 CDN을 사용하지 않는다. [ONNX Runtime Web 배포 안내](https://onnxruntime.ai/docs/tutorials/web/deploy.html)

Docker Compose는 프론트 이미지에 public 파일을 포함하고 백엔드에 동일한 offline-assets 폴더를 읽기 전용으로 마운트한다. **모델을 준비한 뒤** 이미지를 빌드해야 한다. 백엔드 `OFFLINE_BUNDLE_DIR`는 Compose에서 `/offline-assets`다. 모델 파일·manifest 아카이브를 포함한 폴더를 배포 대상에도 복사한다.

인터넷이 없는 보드에 배포할 때는 필요한 아키텍처의 Docker 이미지와 모델 파일을 미리 준비해 가져간다. 실행 중 npm/pip 설치나 외부 모델 다운로드는 필요하지 않지만, 이 작업에서 Orange Pi 장치 자체의 설치·속도는 검증하지 않았다.

## 사용자 흐름

1. 연결된 상태에서 기기 진단의 **모델 준비·업데이트**를 누른다.
2. 준비 완료 후 JPEG/PNG 사진과 작물을 선택해 기기에서 진단한다. 파일은 기본 10MiB 이하, 4천만 픽셀 이하로 제한한다.
3. 기기 이력에 결과·원본 사진·원래 예측 분포·모델/묶음 버전을 저장한다. 혼동쌍이면 안내 부위의 두 번째 사진을 분석하고 두 분포를 0.4:0.6으로 융합한다. S1/S2 시안의 고정 신뢰도나 처리 시간을 강제로 만들지 않는다.
4. 연결 없이 새로고침하고 같은 기기 이력을 확인하거나 새 진단을 할 수 있다.
5. 서버 연결 후 이력의 **서버에 저장**을 누르면 해당 기록을 전송한다. 자동 업로드하지 않는다. 서버는 파일·전체 9클래스 확률·촬영 시각·지원 묶음 버전을 검증하고 당시 묶음의 안내를 저장한다. 기기 결과를 서버에서 다시 추론하지 않으며 `prediction_mode=browser`로 출처를 표시한다.
6. 서버 전송을 시작하기 전에 전송 시도 표시를 기기에 저장한다. 응답 유실도 저장 성공일 수 있으므로 전송한 기록의 사진·분포를 보존하고 재촬영을 잠근다. 동일 결과로 다시 전송하면 멱등 응답으로 성공 여부를 확인한다. 추가 사진은 새 진단으로 저장한다.

기록마다 JSON과 사진을 내보낼 수 있고 기기 기록만 삭제할 수 있다. 삭제 확인은 서버 기록·이미 내보낸 파일을 삭제하지 않는다. 내보낸 JSON을 다시 가져오는 기능은 이번 범위에 포함하지 않았다.

## 저장과 복구의 경계

브라우저 기록은 해당 기기·브라우저·사이트 주소에 속한다. 다른 주소나 브라우저에서는 공유되지 않는다. 영구 저장을 요청하지만 승인 여부는 브라우저에 달려 있고, 사이트 데이터 삭제 또는 저장소 정리로 사라질 수 있다. 중요한 기록은 내보내거나 서버에 저장한다. 저장 공간 부족 시 결과를 화면에 유지하고 같은 결과의 기기 저장을 다시 시도할 수 있다. [MDN Storage API](https://developer.mozilla.org/en-US/docs/Web/API/Storage_API)

서버 저장이 실패하면 서버 전용 `.pending` 초안을 기본 24시간 보존하고 재추론 없는 복구 API를 제공한다. 사진과 초안은 함께 백업한다. 기존 기록이 이후에 바뀌면 예전 복구 결과로 덮어쓰지 않는다. 초안 보관 자체도 실패하면 저장 가능하다고 표시하지 않는다.

농약 사용 조건은 오프라인 묶음에 포함하지 않는다. 서버 이력에서는 당시 병해 안내와 현재 농약 카탈로그를 구분한다. 기기에 설치된 한국어 로컬 음성이 있는 경우 결과 읽기를 제공하고, 없으면 글로 안내한다. 음성 명령/STT, LLM 상담, 카메라 실시간 영상 진단은 구현하지 않았다.

## 검증 결과와 실제 기기에서 남은 확인

- ONNX 변환: 동일 입력 텐서 3개, 서버 PyTorch 대비 최대 logit 차이 `1.4007091522216797e-6`, `atol=rtol=1e-4` 통과.
- 실제 Chrome: 모델 준비 → 실제 WASM 추론 → 네트워크 차단 → 새로고침·이력 복원·새 진단 → 서버 저장 성공 후 응답 유실 → 동일 본문 재전송과 중복 없는 저장 확인. 페이지 JS 오류 없음.
- 백엔드 테스트는 별도 임시 DB/사진 폴더에서 실행한다. 운영 기록을 변경하지 않는다.
- Canvas 사진 리사이즈와 서버 Pillow 전처리는 완전히 같은 구현이 아니다. 동일 텐서의 모델 변환 검증을 사진별 전처리 일치나 병해 정확도 검증으로 해석하지 않는다.
- 휴대폰 Chrome/Safari 메모리·처리 시간·저장소 유지, Orange Pi 속도, 실제 농장 사진 정확도와 로컬 음성 가용성은 대상 장치에서 확인해야 한다. 현재 모델은 경량화·양자화하지 않은 약 94MB 모델이다.

기본 테스트 서버는 별도 DB를 설정한 backend `8000`과 Next.js `3100`이다. 테스트의 단색 사진은 실행 흐름 검증용이며 정확도 평가 자료가 아니다.

```powershell
cd frontend
npm run test:offline
node tests/offline-browser.mjs
```

`TEST_ORIGIN` 환경 변수로 테스트 주소를 바꿀 수 있다. 브라우저 통합 테스트는 Chrome과 생성된 모델 파일, 실행 중인 테스트 전용 백엔드가 필요하다.
