# cropy 제품 요구사항 정의서

**문서 버전:** 1.2 · **기준일:** 2026-10-08 · **작성자:** 김헌영

## 1.1 문서 개요

Cropy의 웹앱과 온디바이스 진단 단말의 기능·환경·제약을 정의한다. 현재 로컬 작업본의 구현, 개발 목표, 실험 결과를 구분한다. 실행 중인 서비스의 배포 버전은 별도로 확인한다.

- CNN: 사진 분류 모델. LLM: 제공된 진단 근거를 설명하거나 기능을 선택하는 모델.
- 모델 분류 점수: softmax 출력으로 실제 발병 확률이나 확진을 의미하지 않는다.
- 재확정: 1차·2차 사진 분포를 융합한 결과 갱신이며 병리학적 확진은 아니다.
- 참고: [기능명세](xpdocs/06_웹앱_기능명세서.md), [아키텍처](ARCHITECTURE.md), [모델 명세](MODEL_SPEC.md), [API](API_SPEC.md).

## 1.2 프로젝트 개요

고추·무·배추 사진에서 병해 6종과 정상 3종을 분류하고, 병해 설명·원인·예방 및 농약 조회 정보를 제공한다. 대상 사용자는 농업인, 고령 농업인과 귀농인이다. 모바일 웹앱을 먼저 개발하고 Orange Pi 5 Plus에 로컬 추론·음성을 통합한다.

혼동되는 후보가 접전이면 판별부위 재촬영을 안내한다. 재촬영·음성 설명의 현장 진단 개선 효과는 별도 검증 대상이다. 모델 크기나 사진의 정보 부족을 오분류의 확정 원인으로 단정하지 않는다.

## 1.3 기능적 요구사항

| ID | 기능과 시나리오 | 현재 상태 |
|---|---|---|
| FR-01 | 사진 선택 또는 기기 파일 입력 촬영 → JPEG/PNG 업로드 → 9클래스 분류 | 구현. 별도 getUserMedia 라이브 카메라는 현 작업본에 없음 |
| FR-02 | 자동 감지 또는 작물 선택 → Top-3·모델 분류 점수 표시 | 구현. 선택 작물로 모델 점수를 강제 변경하지 않음 |
| FR-03 | 상위 두 후보가 무/배추 혼동쌍이고 마진 < 0.20 → 판별부위 안내 → 재촬영 분포 융합 | 구현. 2차 가중치 0.6, 정확도 개선 효과는 미검증 |
| FR-04 | 병해 설명·원인·예방 확인 | 구현. 현재 병해 콘텐츠는 수기 시드 |
| FR-05 | 농약 정보 조회와 작물·병해별 검증 상태 표시 | 구현. 미검증 사용 조건은 숨김. 실제 PSIS 최신 동기화 여부는 별도 확인 |
| FR-06 | 진단 이력 자동 저장·목록·상세와 2차 사진 확인 | 구현. 백엔드 필터·페이지네이션 제공, 현재 목록 UI는 첫 페이지 조회 |
| FR-07 | 큰글씨·반응형·낮은 점수·작물 불일치·시연 결과 안내 | 구현. 최신 디자인 시안 전체의 코드 반영은 별도 작업 |
| FR-08 | 진단·질문 근거 전달 → Qwen 기능 선택/설명 → 검증된 한국어 음성 출력 | 개발 예정. 데이터 초안·검수 자료 존재, 학습·handler·STT/TTS 미검증 |
| FR-09 | 보드에서 로컬 CNN·DB·웹앱 실행, 오프라인·자동 복구 | 배포 계획 존재, ARM64 설치·보드 실측·완전 오프라인 검증 필요 |
| FR-10 | 사용자 인증·농장별 이력 분리 | 후속 범위. 현재 인증 없이 이력 전역 공유 |

## 1.4 비기능적 요구사항

| ID | 요구사항 | 목표 또는 조건 | 확인 상태 |

| NFR-01 | 응답 속도 | 진단 API 5초 이내. 보드 단건 CNN 전처리 포함 1초 이내는 초기 목표 | 대상 기기 실측 필요. 전체 음성·재촬영 목표는 기준선 후 확정 |

| NFR-03 | 자원·전력 | 피크 RAM·온도·전력과 30회 진단/30분 운용 결과 기록 | 수치 한도는 보드 기준선 후 확정, 측정값 없음 |

| NFR-05 | 사용성 | 한국어·모바일 우선·큰글씨, 다음 행동을 알 수 있는 오류 안내 | 구현과 시안 구분. 실제 사용자·휴대폰 검증 필요 |
| NFR-06 | 데이터 보호 | JPEG/PNG·10MiB·4천만 픽셀 제한, 모델/시연 출처 기록 | 구현. 인증·사진 보관기간·접근 제어는 미완성 |
| NFR-07 | 확장성 | 클래스 ID·체크포인트·API 계약 유지, 음성 모듈 별도 통합 | 현재 PyTorch 런타임. ONNX/RKNN/RKLLM은 추가 작업 |
| NFR-08 | 업데이트 | 모델 해시·전처리 추적, 교체 후 재시작·ready 확인·복구 | 수동 운영 절차. OTA는 미구현 |

성능 기록은 [모델 명세](MODEL_SPEC.md)에 데이터·입력·분할·버전별로 분리한다. 최신 후보의 높은 검증 정확도를 현재 서비스나 독립 test 성능으로 표시하지 않는다.

## 1.5 환경 요구사항

- 현재 구현: Next.js 15/React 19, FastAPI, PyTorch, SQLite, 로컬 이미지 파일. 설치 선언은 [기술 스택](TECH_STACK.md) 참조.
- 단말 목표: **Orange Pi 5 Plus / RK3588 / ARM64 / RAM 16GB**. 실제 OS·커널·NPU 드라이버·주변장치는 수령 환경에서 확정.
- 스마트폰은 웹 클라이언트이며 스마트폰 내부 CNN 추론은 별도 후보 경로다. 라이브 카메라·마이크 통합 시 신뢰할 수 있는 HTTPS 필요.
- PSIS는 카탈로그 갱신용 외부 연동이다. 로컬 카탈로그 조회와 인터넷 재동기화를 구분한다.

## 1.6 제약사항

2026년 9~12월 학기 일정과 5명 역할 분담을 기준으로 개발한다. 단말 부품 예산안은 40만 원이며 실제 구매 내역과 구분한다. 보드·변환 도구 호환, 독립 평가 자료, 무노균병 촬영 조건, 실제 음성 및 데이터 사람 검수가 제약이다.

최신 LLM 초안은 7기능 2,800개(train 2,240/validation 560)이며 사람 승인 0개다. AI 검수 결과는 학습 승인이나 실제 음성 성능이 아니다. 인큐박스·인증·작물 확장은 별도 후속 범위로 관리한다.
