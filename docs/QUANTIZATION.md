# Cropy 모델 양자화 및 온디바이스 포팅 계획

**갱신:** 2026-10-08 · **상태:** 실행·측정 전 계획

## 1. 범위와 현재 상태

목표 단말은 **Orange Pi 5 Plus / RK3588 / ARM64 / RAM 16GB**다. 현재 백엔드는 PyTorch 체크포인트를 읽는다. CNN ONNX/RKNN 변환 스크립트·런타임 분기, Qwen RKLLM 및 스마트폰 네이티브 추론은 현재 구현되어 있지 않다.

기본 파일은 ResNet50/9클래스/약 94.4MB이며 입력 메타데이터가 없어 224로 폴백한다. 최신 256·384 실험 후보와 구분한다. 모델·분할별 수치는 [MODEL_SPEC](MODEL_SPEC.md), 상세 최신 분석은 [10월 6일 보고서](../report/AI_모델_개선_보고서_20261006.md)를 따른다.

## 2. 포팅 순서와 선택 기준

1. 같은 모델·전처리·클래스 순서로 보드 PyTorch CPU 기준선을 확보한다.
2. 전체 진단의 지연·피크 RAM·온도·전력을 측정한다. 목표를 충족하면 CPU 경로를 유지할 수 있다.
3. 미달 시 CPU 설정·ONNX·RKNN INT8 경로를 비교한다. 최적화마다 변경 전후 결과를 기록한다.
4. Qwen/RKLLM은 CNN/RKNN과 별도 도구·모델·산출물로 관리한다. 두 모델의 NPU/메모리 경합을 측정한다.

스마트폰 내부 ONNX Runtime 추론은 별도 후속 후보이며 현재 모바일 웹앱과 동일한 구현으로 취급하지 않는다.

## 3. CNN 변환 계획

```text
선정 PyTorch .pth → FP32 ONNX → 동일 평가로 변환 정합 확인
                              ├─ RKNN 도구의 캘리브레이션·INT8 → .rknn
                              └─ 후속 모바일 ONNX 양자화 → quant.onnx
```

ONNX INT8은 RKNN 변환의 필수 중간 산출물로 삼지 않는다. export 전에 체크포인트의 arch·num_classes·classes·img_size·model_state_dict를 확인한다. 입력은 선정 모델의 실제 해상도와 RGB/ImageNet 정규화를 사용한다. 최신 후보에 224를 일괄 적용하지 않는다.

서버의 이미지 리사이즈·정규화와 변환 그래프의 처리 범위를 명시하여 정규화를 이중 적용하지 않는다. 변환기가 요구하는 ONNX opset·레이아웃·도구 버전은 설치한 패키지에서 확인하고 실행 기록에 고정한다.

캘리브레이션은 train에서 클래스당 30~60장, 총 300~500장을 초기 후보로 선택한다. 클래스·촬영 조건의 커버리지를 확인하며 validation/test를 캘리브레이션으로 사용하지 않는다.

## 4. 검증과 목표

| 항목 | 방법 / 초기 기준 | 현재 상태 |
|---|---|---|
| 모델 크기 | FP32·ONNX·INT8 실제 파일 크기 기록 | 기본 .pth 약 94.4MB, 변환 파일 없음 |
| 전체 정확도 | 같은 고정 평가 자료·전처리로 비교, 초기 허용 하락 ≤1.5%p | 기준 확정·변환 평가 필요 |
| 클래스별 성능 | 정밀도·재현율·F1·혼동행렬, 초기 클래스별 하락 ≤3%p | 특히 무노균병 저하 별도 판단 |
| 재촬영 | 전체 확률 분포·발동률·융합 결과와 보조 모델 영향 비교 | 실제 변환 경로 미검증 |
| 속도 | 첫 로드와 예열 후 단건/재촬영 중앙값·p95 구분 | 보드 단건 CNN 전처리 포함 1초 이내는 초기 목표 |
| 자원·전력 | 전체 스택 RAM·온도·전력과 30회/30분 반복 기록 | 실측값 없음 |

INT8 후 파일 크기·속도·전력 개선폭은 아직 측정되지 않았다. 4배 축소·수십 ms·정확도 손실 1%p 이하를 실측 결과로 제시하지 않는다. 허용 하락 기준은 팀의 채택 기준이며 특정 질병을 놓치는 문제가 악화되면 전체 정확도가 높아도 채택을 재검토한다.

불합격 시 캘리브레이션 대표성·전처리·지원 연산을 먼저 점검하고 혼합 정밀도 또는 QAT를 검토한다. 정확도 보완 효과는 실험으로 확인한다.

## 5. 보조 모델과 백엔드 통합

현재 보조 ResNet18은 ENABLE_PAIR_MODEL=true일 때만 활성화된다. prepare_pair.py는 학습 데이터 준비 도구이며 양자화된 모델을 생성하지 않는다. 필요하면 보조 모델도 별도로 학습·변환·평가하고 쌍 밖 확률 질량 보존을 확인한다.

ML_RUNTIME=torch|rknn은 향후 설정 제안이며 현재 앱이 읽는 환경변수가 아니다. 실제 런타임 선택 코드와 출력 계약 검증을 추가해야 한다. 변환 모델의 해시·전처리 버전을 기록하고 모델 교체 후 재시작·ready·재촬영 충돌 동작을 검증한다.

## 6. Qwen/RKLLM 및 음성

Qwen3.5 후보의 실제 모델 ID·revision·tokenizer·변환 지원을 확정한 뒤 기본 예제로 변환과 보드 추론을 검증한다. W8A8은 계획이며 현재 성공한 산출물이 아니다. 기능 토큰 데이터의 사람 승인, 실제 토큰 ID·종료 동작, handler/TTS 소량 시험이 학습 전 선행 작업이다.

원본/학습 모델과 양자화 모델을 같은 질문으로 비교하여 근거 준수·기능 선택·한국어 응답·첫 토큰 지연·생성 속도·RAM을 기록한다. 상세 조건은 [LLM 계획](LLM_FINETUNING_PLAN.md)과 [배포 가이드](ORANGEPI5_DEPLOY.md)를 따른다.

## 7. 산출물과 완료 조건

필요 산출물은 export/변환 스크립트, 캘리브레이션 목록, 모델 파일·해시·환경, 변환 전후 성적표, 보드 실측 기록, 런타임 통합·복구 확인 결과다. 파일 생성만으로 포팅 완료 처리하지 않는다. CNN CPU 기준선 → 필요 시 CNN 최적화, Qwen 기본 검증 → 필요 시 학습의 순서로 진행한다.
