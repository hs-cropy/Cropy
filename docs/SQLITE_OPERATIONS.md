# SQLite 마이그레이션 운영 메모

DB는 WAL 모드로 열려 DB 파일 옆에 `-wal`, `-shm` 파일이 생긴다. WAL은 공유 메모리 파일을 쓰므로 DB를 로컬 디스크에 둔다. 네트워크 드라이브나 OneDrive 같은 동기화 폴더 아래에서 서버를 실행하지 않는다.

## 외래키 위반으로 기동이 중단되는 경우

`foreign_key_check` 실패 시 기존 이력을 보호하기 위해 기동을 중단한다.

1. 서버와 DB에 쓰는 프로세스를 중지하고, 현재 DB를 SQLite backup API로 별도 보존한다. WAL 사용 중에는 DB 파일만 복사하지 않는다.
2. 별도 복사본에서 `PRAGMA foreign_key_check;`를 실행해 위반 테이블·행·참조 대상을 확인한다.
3. 원본 근거에 따라 누락된 참조 데이터를 복구하거나 검증된 백업으로 복원한다. 외래키 검사를 끄거나 진단 이력을 일괄 삭제해 우회하지 않는다.
4. 복구본에서 `PRAGMA integrity_check;`가 `ok`, `PRAGMA foreign_key_check;`가 0행인지 확인한다. 서버가 정지된 상태에서 복구본으로 교체하고 재기동한다. 교체 전 DB와 WAL/SHM 파일은 함께 별도 보존해 이전 WAL이 복구본에 적용되지 않도록 한다.

시드나 관리 기능에서 데이터를 삭제할 때는 참조하는 매핑 행을 먼저 처리한다. 진단에서 참조하는 병해 삭제는 이력 보존 정책을 먼저 확인한다.

## 백로그: 백업 보관·정리 정책

- 상태: 미구현. `.backup-*` 자동 삭제는 현재 없다.
- 보드의 저장 용량과 운영 복구 요구에 맞춰 보관 기간·개수·최소 여유 공간을 결정한다.
- 최근 복원 검증 완료 백업을 보존하고, 삭제 대상 미리보기와 명시적 정리 절차를 제공한다.
- 마이그레이션 실패 조사에 필요한 백업은 정리 대상에서 제외한다.
