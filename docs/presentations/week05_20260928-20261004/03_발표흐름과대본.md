## 1. 프로젝트 소개

안녕하세요. 크래파스 팀의 cropy 수행계획과 현재까지의 주간 실적을 발표하겠습니다. cropy는 고추·무·배추 사진을 분석해 병해 후보와 관련 정보를 보여 주고, 판단이 어려우면 추가 촬영을 안내하는 서비스입니다. 먼저 어떤 서비스를 목표로 하는지 설명하고, 3주차와 4주차에 수행한 작업, 5주차에 진행 중인 내용을 말씀드리겠습니다.

화면: 프로젝트명, 팀원, 사진 입력부터 이력 저장까지의 흐름.

## 2. 문제와 목표

저희가 해결하려는 문제는 사진을 찍은 뒤 사용자가 다음 행동을 결정하기 어렵다는 점입니다. 비슷한 병징은 한 장의 사진에서 구분하기 어려울 수 있고, 결과를 보더라도 관련 정보를 다시 찾아야 합니다. 그래서 병해 후보와 정보를 함께 보여 주고, 필요한 경우 무엇을 추가로 촬영해야 하는지 안내하는 흐름을 설계했습니다. 큰 글씨와 음성 안내, 통신이 없어도 동작하는 단말로 확장하는 것이 목표입니다. 이 사용성 효과는 앞으로 현장에서 확인할 계획입니다.

화면: 추가 관찰 안내, 정보 연결, 접근성의 세 가지 목표.

## 3. 개발 내용과 현재 상태

현재 범위는 세 작물의 병해 여섯 종류와 정상 세 종류, 총 아홉 클래스입니다. 사진을 ResNet50으로 분류하고, FastAPI가 관련 정보와 진단 이력을 관리하며 Next.js 화면이 결과를 보여 줍니다. 사진 업로드와 결과·이력·재촬영 흐름의 구현 및 검증 기록을 확보했습니다. 카메라 브랜치는 별도 환경에서 연결을 확인했고, 실제 휴대폰 검증과 통합은 남아 있습니다. Orange Pi에서의 오프라인 실행, LLM 설명과 음성 입출력은 후속 단계입니다. 특히 LLM은 병을 새로 판정하는 역할이 아니라 확인된 결과를 쉽게 설명하도록 계획했습니다.

화면: 수행계획서의 개발 목표·현재 상태 표. 현재 웹 경로와 계획 중인 음성 경로를 구분한다.

## 4. 역할과 일정

김헌영은 PM과 모델·데이터 평가, 김민서는 화면과 접근성, 박성호는 API와 데이터베이스, 고명준은 카메라와 음성, 이서하는 배포와 장치를 담당합니다. 초반에는 웹과 모델의 기준을 정리하고, 중반에는 보드와 음성을 연결하며, 후반에는 통합 성능과 안정성을 검증합니다. 현재는 초기 작업의 결과를 검토하면서 다음 통합 단계로 넘어가는 시점입니다. 이후 설명하는 실적은 역할표만으로 배분하지 않고 실제 작업 기록을 기준으로 정리했습니다.

화면: 역할표와 4단계 일정.

## 5. 3주차 실적과 문제 해결

3주차의 핵심은 평가 데이터를 점검한 것입니다. 기존 모델은 축소 검증 이미지 637장 중 613장을 맞혀 96.23%였습니다. 일반 샘플링과 균형 샘플링으로 추가 학습했지만 기존 성능을 넘지 못했습니다. 원본 이미지를 넣는 것만으로도 성능이 좋아지지는 않았습니다.

이후 이미지 해시를 비교해 학습과 검증 사이에 동일 이미지 두 쌍, 학습과 테스트 사이에 네 쌍이 있다는 사실을 확인했습니다. 그래서 높은 점수만 유지하기보다 평가 기준부터 다시 마련했습니다. 원천 라벨 약 9만 1천 개를 조사해 현재 이미지 4,246장을 연결하고 수집 작업자 기준의 분할 후보를 만들었습니다. 여기서 작업자는 농장이나 개체와 같지 않으므로, 완전한 현장 독립성을 확보했다고 말할 수는 없습니다.

화면: 기존 평가 → 중복 발견 → 라벨 대조 → 새 분할 설계.

## 6. 4주차 모델 비교 결과

4주차에는 학습 내 중복 11장을 제거한 4,235장 번들을 사용했습니다. 학습 2,728장, 검증 785장, 테스트 722장입니다. 같은 분할과 같은 seed에서 입력 크기 224와 256을 비교했습니다.

검증 정답은 721장에서 726장으로 늘었고, 정확도는 91.85%에서 92.48%로 약 0.64퍼센트포인트 개선됐습니다. 병해를 정상으로 잘못 분류한 경우도 29건에서 22건으로 줄었습니다. 하지만 무 두 병해 사이의 혼동은 28건에서 31건으로 늘었습니다. 기존 오류 17건을 개선하는 동안 새로운 오류 12건도 발생했습니다.

따라서 256이 모든 면에서 더 좋다고 결론내리지 않았습니다. 후보로 보존하고 취약 사례를 검토하고 있습니다. 이 수치는 검증 세트 결과이며 최종 테스트나 현장 정확도가 아닙니다. 앞서 나온 96.23%와는 데이터 조건이 달라 직접적인 성능 하락으로 비교하지 않습니다.

화면: 주간보고서의 224·256 비교표. 정답 5장 증가와 무 병해 혼동 3건 증가를 함께 표시한다.

## 7. 4주차 서비스 개선 결과

서비스에서는 진단 결과가 어떤 근거에서 나왔는지 보존하는 작업을 했습니다. 실제 모델과 예시 진단을 구분하고, 잘못된 모델 출력을 차단하며, 모델과 전처리 버전을 이력에 기록했습니다. 선택한 작물과 예측 작물이 다르면 화면에서 알려 주도록 했습니다.

농약은 제품 정보와 작물·병해별 사용 조건을 분리하고 미검증 조건을 숨기도록 개선했습니다. DB 백업과 마이그레이션, 이미지 검증과 요청 제한도 보완했습니다. 9월 28일 기록에서 백엔드 테스트는 183개 통과, 1개 제외였고 프론트엔드 컴파일과 타입 검사도 통과했습니다. 카메라는 별도 복제본의 가상 영상으로 진단과 이력까지 연결했습니다. 이 결과는 구현과 로컬 검증의 근거이며 실기기나 운영 배포 완료를 뜻하지는 않습니다.

화면: 결과 출처·작물 불일치·농약 검증·이력 보존의 네 가지 개선 항목.

## 8. 5주차 중간 현황

5주차는 10월 1일까지의 중간 현황입니다. 무 병해 학습 이미지 513장의 촬영면을 AI로 1차 검토했습니다. 앞면 추정 97장, 뒷면 추정 384장, 판단 불가 32장입니다. 두 병해 모두 앞뒷면 추정 사진이 있으므로, 특정 면이 없어서 혼동한다고 단정할 수 없었습니다.

다음으로 학습 12장과 이미 분석한 검증 오류 8장을 골라 전문가 검수용 갤러리와 양식을 준비했습니다. 아직 전문가에게 전달하거나 답변을 받은 단계는 아니며, 라벨과 모델도 바꾸지 않았습니다. 이와 함께 의존성 경고의 영향과 수정 순서를 검토했고, 오늘 프론트엔드와 백엔드 실행 및 실제 모델 준비 상태를 확인했습니다.

화면: 촬영면 집계와 전문가 검수 준비 상태. AI 추정과 전문가 확정을 명확히 구분한다.

## 9. 실행 화면과 다음 계획

여기서는 실행한 웹 화면을 보여 드리겠습니다. 사진 입력과 작물 선택 화면, 결과와 이력으로 이어지는 구성을 확인할 수 있습니다. 오늘 확인한 범위는 홈 응답과 API 연결, 실제 모델이 로드되었다는 준비 상태입니다. 새로운 이미지의 진단 성능을 오늘 다시 측정한 것은 아닙니다.

다음 단계는 세 가지입니다. 첫째, 취약 사례를 전문가와 검토하고 필요한 데이터 조건을 정합니다. 둘째, 카메라를 실제 휴대폰에서 확인하고 기능별 변경을 리뷰·통합합니다. 셋째, 배포할 모델의 규격을 확정한 뒤 보드에서 실제 진단과 속도·메모리·온도를 측정합니다. CNN은 CPU 기준선을 먼저 얻고 필요한 최적화를 결정합니다. LLM과 음성은 각각 검증한 뒤 연결하며, 인터넷 차단과 재부팅 후에도 이력이 유지되는지 확인하겠습니다.

시연 준비:

1. `http://localhost:3000`에서 홈과 화면 구성을 보여 준다.
2. API 준비 상태의 `model_loaded=true`와 `prediction_mode=model`을 확인한다.
3. 실제 사진 진단을 시연하려면 발표 전에 해당 이미지·결과·이력 흐름을 별도로 리허설한다.
4. 연결 문제에 대비한 화면 캡처는 촬영일과 검증 범위를 함께 표시한다.

## 10. 기대효과와 마무리

cropy는 사진의 분류 결과와 함께 사용자가 다음에 무엇을 확인할지 안내하는 서비스를 목표로 합니다. 지금까지 평가 데이터의 중복을 확인해 비교 기준을 다시 만들었고, 같은 조건의 모델 실험과 진단 이력·정보 표시 개선을 진행했습니다. 앞으로는 전문가 검수와 실제 장치 검증으로 현재 결과가 현장에서도 유효한지 확인하겠습니다. 이상으로 수행계획과 주간 실적 발표를 마치겠습니다. 감사합니다.
