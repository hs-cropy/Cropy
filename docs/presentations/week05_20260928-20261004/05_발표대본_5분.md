# cropy 데이터셋 구축 및 성능 개선 발표 대본 — 5분

발표자: 김헌영 / 팀명: 크래파스

근거: [데이터셋 구축 및 성능 개선 결과 보고서 3·4주차](../../reports/week05_20260928-20261004/데이터셋_구축_및_성능_개선_결과_보고서_20260928.md)

아래 여섯 구간의 본문을 읽는다. 제목과 시간은 읽지 않는다. 약 5분 분량으로, 실제 속도와 화면 전환에 맞춰 리허설에서 조정한다.

## 1. 무엇을 했는지 — 0:00~0:30

안녕하세요. 크래파스 팀의 김헌영입니다. 저희 cropy는 고추, 무, 배추 사진을 보고 어떤 병인지 구분하는 서비스입니다. 현재는 병 여섯 종류와 작물별 정상 상태를 합쳐 아홉 가지로 분류하고 있습니다.

3주차와 4주차에는 두 가지를 확인했습니다. 먼저, AI가 학습하고 평가받는 사진이 제대로 구성되어 있는지 점검했습니다. 다음으로, 사진의 입력 크기를 바꾸면 병을 더 잘 구분하는지 비교했습니다. 그 과정에서 발견한 문제와 결과를 말씀드리겠습니다.

## 2. 더 학습시키는 것만으로는 나아지지 않았습니다 — 0:30~1:15

처음에는 기존 모델을 더 학습시키면 정확도가 올라갈 것으로 기대했습니다. 기존 모델은 평가용 사진 637장 중 613장을 맞혔고, 정확도는 약 96퍼센트였습니다.

사진을 일반적인 방식으로 골라 학습시키는 방법과, 사진 수가 적은 종류를 더 자주 보여 주는 방법을 비교했습니다. 하지만 두 방법 모두 기존 결과보다 좋아지지 않았습니다.

원본 사진을 사용하면 더 잘 맞힐지도 확인했습니다. 같은 모델로 비교했을 때 원본 사진은 약 95퍼센트, 축소한 사진은 약 96퍼센트였습니다. 원본을 쓴다고 무조건 좋아지는 것은 아니었습니다.

또 틀린 사진 24장 중 13장이 무의 두 병을 서로 혼동한 경우였습니다. 그래서 학습을 더 하기 전에, 어떤 사진에서 왜 틀리는지 먼저 살펴보기로 했습니다.

## 3. 학습 사진과 평가 사진을 다시 나눴습니다 — 1:15~2:15

사진을 점검하다 보니 중요한 문제가 발견됐습니다. 학습용 사진과 평가용 사진에 똑같은 사진이 일부 들어 있었습니다. 학습과 검증 사이에는 두 쌍, 학습과 최종 테스트 사이에는 네 쌍이 있었습니다.

쉽게 말하면 공부할 때 본 문제가 시험에도 그대로 나온 상황입니다. 이런 사진이 섞여 있으면, 처음 보는 사진도 잘 맞힐 수 있는지 충분히 확인하기 어렵습니다.

그래서 사진에 붙은 정답 정보와 촬영 정보를 다시 확인했습니다. 현재 이미지 4,246장을 각각의 정답 정보와 연결하고, 사진을 수집한 작업자를 기준으로 자료를 나눴습니다. 같은 작업자의 사진이 학습용과 평가용에 섞이지 않도록 한 것입니다.

학습 자료 안에서 똑같은 사진 11장도 제거했습니다. 실제 실험에는 학습용 2,728장, 중간 평가용 785장, 마지막 확인용 722장을 사용했습니다.

다만 작업자가 다르다고 농장이나 작물 개체까지 모두 다르다고 보장할 수는 없습니다. 이번에는 확인 가능한 정보를 바탕으로 중복을 줄이고, 더 믿을 수 있는 비교 기준을 마련했습니다.

## 4. 사진 크기를 키우니 다섯 장을 더 맞혔습니다 — 2:15~3:25

4주차에는 새로 나눈 자료로 사진 입력 크기를 비교했습니다. AI에 넣는 사진을 가로세로 224칸으로 맞춘 경우와 256칸으로 맞춘 경우입니다. 같은 모델 구조와 학습 조건을 사용해 사진 크기에 따른 차이를 살펴봤습니다.

평가용 사진 785장 가운데 작은 입력에서는 721장, 큰 입력에서는 726장을 맞혔습니다. 정확도는 약 91.85퍼센트에서 92.48퍼센트로 올라갔습니다. 다섯 장을 더 맞힌 것입니다.

병든 사진을 정상이라고 잘못 판단한 경우도 29건에서 22건으로 줄었습니다. 이 부분은 개선된 결과입니다.

하지만 모든 결과가 좋아진 것은 아닙니다. 무검은무늬병과 무노균병을 서로 혼동한 경우는 오히려 28건에서 31건으로 늘었습니다. 사진별로 보면, 전에 틀렸던 17장은 맞혔지만 전에 맞혔던 12장은 새로 틀렸습니다.

그래서 전체 정확도가 조금 높아졌다는 이유만으로 서비스 모델을 바꾸지는 않았습니다. 큰 입력의 모델은 비교 후보로 남겨 두었습니다.

앞에서 말씀드린 기존 약 96퍼센트와 이번 약 92퍼센트는 평가 사진과 실험 조건이 다릅니다. 두 숫자를 바로 비교해서 성능이 떨어졌다고 해석하면 안 됩니다. 이번 개선 여부는 같은 조건에서 비교한 두 모델을 기준으로 판단했습니다.

## 5. 결과를 보여 주는 과정도 점검했습니다 — 3:25~4:05

모델 실험과 함께 서비스가 결과를 제대로 전달하는지도 확인했습니다. 모델이 잘못된 형식의 결과를 내보내면 차단하고, 어떤 모델과 사진 처리 방식으로 진단했는지 기록하도록 개선했습니다.

결과의 점수가 낮거나, 사용자가 고른 작물과 AI가 판단한 작물이 다를 때는 화면에서 확인하도록 안내했습니다.

팀원이 만든 카메라 기능도 별도 환경에서 연결해 봤습니다. 가상 카메라로 사진을 찍고, 실제 모델로 분석한 뒤 결과와 이력을 확인하는 흐름까지 점검했습니다. 다만 미리보기에 보이는 범위와 저장되는 사진 범위가 다른 문제도 발견했습니다. 실제 휴대폰에서는 이 부분을 더 확인해야 하며, 가상 카메라의 결과를 정확도 평가에 사용하지는 않았습니다.

## 6. 다음에 할 일과 마무리 — 4:05~5:00

다음에는 무의 두 병을 혼동한 사진과, 이번 실험에서 새롭게 틀린 사진을 먼저 살펴보겠습니다. 병의 특징이 사진에 잘 보이는지, 촬영 조건이 다른지, 정답 정보를 다시 확인해야 하는지 구분할 계획입니다. AI가 틀렸다는 이유만으로 정답을 바꾸지는 않겠습니다.

또 다른 작업자와 촬영 환경의 사진을 보강하고, 같은 기준으로 실험을 반복해 개선이 다시 나타나는지 확인하겠습니다. 모델을 최종 선택한 뒤에는 따로 남겨 둔 테스트 사진으로 마지막 평가를 진행하겠습니다. 실제 휴대폰에서 사진의 범위와 방향, 품질, 처리 시간도 확인할 예정입니다.

3주차에는 데이터의 중복 문제를 찾아 평가 기준을 다시 만들었습니다. 4주차에는 사진 크기를 바꿔 다섯 장을 더 맞혔지만, 특정 병을 구분하는 성능은 나빠질 수 있다는 점도 확인했습니다.

앞으로는 전체 정확도뿐 아니라 어떤 병을 놓치는지도 함께 보면서 모델을 개선하겠습니다. 감사합니다.

## 발표 전 확인 — 읽지 않는 메모

- 성능 수치는 중간 평가용인 **검증 세트** 결과다. 최종 테스트나 실제 농가에서의 정확도를 측정한 결과는 아니다.
- ‘사진 224칸·256칸’은 각각 **224×224픽셀·256×256픽셀**을 쉽게 설명한 표현이다.
- 시간 배분은 30초 + 45초 + 60초 + 70초 + 40초 + 55초 = **300초**다. 실시간 시연은 포함하지 않았다.
- 2분 15초에 사진 크기 비교, 4분 5초에 다음 계획으로 넘어가는지 리허설한다. 시간이 넘치면 2절의 원본·축소 사진 비교 문단을 줄인다.
