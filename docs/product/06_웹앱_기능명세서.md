# Cropy 웹앱 기능 명세서

**갱신:** 2026-10-12 · **버전:** 0.3 · **대상:** 최신 develop 반영 구현과 후속 검증

FE=김민서, CAM=고명준, BE=박성호, ML=김헌영, INF=이서하. 역할은 기존 팀 분담 기준이며 실제 완료 기록과 구분한다.

## 1. 현재 화면과 공통 동작

| 화면 | 실제 라우트/구현 | 동작 |
|---|---|---|
| 홈·업로드·진단 결과 | /, DiagnoseForm·DiagnosisResult | 별도 /result/[id] 없이 홈 아래에 결과 표시 |
| 재촬영 | 홈 또는 이력 상세, RecapturePanel | 서버 recapture 지침과 file 입력으로 추가 사진 전송 |
| 이력 목록 | /history | 작물·등급 필터, 20개 단위 이전/다음 페이지, 재조회·카드 상세 이동 |
| 기기 진단 | /offline/index.html | 모델 준비 후 ONNX/WASM 진단·IndexedDB 저장·수동 서버 동기화 |
| 이력 상세 | /history/[id] | 원본·2차 사진·결과 조회, 남은 recapture 지침으로 재촬영 가능 |

큰글씨는 TextSizeToggle로 전환하고 localStorage에 저장한다. VoiceToggle로 음성 안내를 켜고 끄며, Web Speech API로 홈·촬영·진단 중·결과 또는 재촬영 지침을 읽는다. 브라우저의 음성 제공과 사용자 상호작용 제한이 적용된다. 한국어·모바일/데스크톱 반응형을 사용한다. 10월 7일 [UI/UX 보고서](../reports/week06_20261005-20261011/Cropy_UIUX_디자인_주간보고서_20261007.md)의 디자인 시안 전체가 코드에 반영된 것은 아니다.

## 2. 촬영·업로드·진단

| ID | 현재 동작 | 담당 |
|---|---|---|
| WEB-01 | 자동 감지 또는 고추·무·배추 선택. 선택하지 않으면 자동 감지 | FE |
| WEB-02 | 지원 환경에서 getUserMedia 카메라 오버레이·전후면 전환·사진 캡처 제공. 갤러리 선택 및 미지원 환경의 capture=environment 파일 입력 제공 | FE+CAM |
| WEB-03 | 선택 이미지 미리보기, 다시 선택, 사진 없이 제출 시 오류 안내 | FE |
| WEB-04 | 진단 버튼 → 로딩 → POST /api/v1/diagnose → 홈에 결과 표시 | FE+BE |
| WEB-05 | 오류 메시지 표시. 제출 실패 시 선택 사진 유지·재시도, 저장 실패 시 결과 유지·다시 저장 | FE |

CameraCapture는 라이브 미리보기에서 정지 사진을 캡처하며 실시간 영상 진단은 아니다. capture 파일 입력 동작은 기기·브라우저에 따라 다르다. 선택 사진은 JPEG/PNG MIME과 10MiB 한도를 클라이언트에서 검사하고 실제 형식·디코딩은 서버가 확인한다. 화면 이탈 시 AbortController로 요청을 취소하지만 15초 자동 타임아웃과 업로드 사진의 긴 변 1280 리사이즈는 구현되지 않았다.

백엔드는 실제 형식 JPEG/PNG, 파일 10MiB, 4천만 픽셀과 전체 디코딩을 검사한다. WebP는 허용하지 않는다. multipart 본문 전체에는 파일 한도+64KiB 제한이 추가 적용된다. 서버는 원본 바이트를 유지하며 EXIF 자동 회전·재인코딩하지 않는다.

## 3. 결과·농약 정보

- 병명·Top-3와 모델 분류 점수를 표시한다. confidence는 실제 발병 확률이 아니다.
- category=normal은 정상 클래스 분류로 표시한다. 사진만으로 질병 부재를 보증하지 않는다.
- 서버의 decision_reasons에 low_confidence가 있으면 불확실성 안내, prediction_mode=mock에는 시연용 표시, crop_mismatch에는 선택/예측 작물 불일치 안내가 있다.
- severity는 DB의 병해 속성이며 사진에서 측정한 진행 정도가 아니다.
- description/causes/prevention을 표시한다. 현재 병해 콘텐츠는 수기 시드다.
- 농약 항목이 있으면 제품·검증 상태와 제공된 사용 조건을 표시한다. verification_status가 verified가 아니면 경고를 표시하고 백엔드에서 미검증 사용 조건을 null 처리한다.
- 농약 배열이 비었을 때 현재 코드는 농약 섹션을 렌더링하지 않는다. 별도 빈 목록 안내는 후속 UX 항목이다.

## 4. 판별부위 재촬영

recapture 유무를 서버가 결정한다. 상위 2후보가 무/배추 혼동쌍이고 마진 <0.20일 때 지침을 제공한다. 프론트는 region/instruction/candidates를 표시하고 추가 file을 POST /api/v1/diagnose/{id}/refine으로 전송한다.

백엔드는 저장된 1차 분포와 2차 분포를 0.4/0.6으로 융합한다. 보조 모델은 ENABLE_PAIR_MODEL=true일 때만 적용하며 기본 비활성화다. 성공하면 같은 이력을 갱신하고 recapture=null을 반환한다. 실패하면 이전 결과를 유지한다. 모델·전처리·모드 또는 동시 수정 충돌은 409다.

결과 화면은 사진 2장과 분석 상태를 표시한다. 이미지에서 특정 포자층이 확인되었다는 설명을 자동 생성하지 않는다. 실제 재촬영의 정확도 개선은 미검증이다.

## 5. 이력

GET /api/v1/history와 fetchHistory는 page/size/crop_type/severity를 지원한다. 목록은 작물과 등급(high/medium/low)을 필터링하며 조건 변경 시 1페이지로 돌아간다. 페이지당 20개, 이전/다음 버튼, 조건에 맞는 건수, 불러오기 실패 시 재조회, 재촬영 결과 갱신 배지를 제공한다. total과 unfiltered_total로 전체 이력 없음과 조건에 맞는 이력 없음을 구분한다. 등급은 DB 병해 속성이며 사진에서 측정한 진행 정도가 아니다. 무한 스크롤·월별 구분은 미구현이다. 상세 화면은 DiagnosisResult와 RecapturePanel을 재사용하고 저장 당시 안내와 현재 농약 조회 정보를 구분한다.

현재 로그인·농장별 이력 분리는 없고 이력은 전역 공유다. 기존 출처 없는 기록은 legacy로 표시하며 실제 모델 사용으로 추정하지 않는다.

## 6. API와 파트 간 계약

| 접점 | 현재 계약 |
|---|---|
| ML→BE | .pth, arch/classes/num_classes/model_state_dict, img_size 없으면 224 폴백, 클래스 ID 0~8 |
| BE→FE | [API_SPEC](../api/API_SPEC.md)와 Pydantic DiagnoseResponse/PaginatedHistory |
| FE→BE | multipart file, 선택 crop_type은 query, 경로 prefix /api/v1 |
| INF→전원 | Docker Compose와 ready 확인. BACKEND_ORIGIN은 빌드 인자 |
| CAM→FE | CameraCapture의 사진 File을 DiagnoseForm에 전달. 촬영·결과 TTS 안내 연동 구현, 실제 기기 검증 필요 |

상태 확인은 GET /api/v1/health(생존), GET /api/v1/ready(실제 모델·DB 준비)다. 병해 조회는 /api/v1/diseases와 /api/v1/diseases/{id}다. 현재 홈은 상태/병해 API를 별도로 조회하지 않는다.

## 7. 후속 기능과 검증

실제 휴대폰 권한/전후면/복귀, STT와 Qwen handler, 보드 음성 통합, 요청 시간 제한, 농약 빈 상태, 최신 UI 시안 전체 반영을 후속 작업으로 관리한다. [과거 가상 카메라 통합 기록](../../output/camera_integration_20260928.md)은 실제 휴대폰 검증을 의미하지 않는다. 라이브 카메라·브라우저 TTS·이력 필터/페이지·저장 복구는 현재 코드에 포함되어 있다.

Orange Pi 목표는 5 Plus/RK3588/16GB다. 스마트폰 브라우저 자체 추론은 구현되었으며 실제 휴대폰 성능·저장소 유지와 보드 실측은 미검증이다. 인증·작물 확장은 후속 범위다. 코드 기반 요구사항은 [PRD](PRD.md), 시스템 구조는 [ARCHITECTURE](../architecture/ARCHITECTURE.md)를 따른다.

## 8. 저장 복구와 브라우저 오프라인 진단

진단·재촬영 요청은 멱등 키를 사용한다. 재촬영 실패 시 같은 사진으로 재시도할 수 있다. save_status=failed 결과는 화면에 유지하고 recovery_token이 있으면 POST /api/v1/results/{token}/save로 재추론 없이 다시 저장한다. 복구 초안의 보관 시간과 충돌 제한은 [운영 가이드](../operations/BACKEND_OPERATIONS.md)를 따른다.

#58의 브라우저 오프라인 진단은 develop에 반영되었다. 별도 기기 진단 화면에서 보안 컨텍스트(HTTPS 또는 개발용 localhost)로 모델·WASM을 준비하면 연결 없이 진단·재촬영·기기 이력 저장이 가능하다. 서버 연결 후 사용자가 서버 저장을 요청하며 자동 전송하지 않는다. 서버는 재추론하지 않고 prediction_mode=browser로 구분한다. 농약 사용 조건은 오프라인 묶음에 포함하지 않는다. 한국어 로컬 음성이 있을 때 결과 읽기를 제공한다.

[오프라인 가이드](../operations/OFFLINE_WEB.md)의 Chrome 검증은 과거 실행 기록이다. 이번 문서 정리에서 재실행한 결과가 아니며 실제 휴대폰·Orange Pi 성능, 저장소 유지, 로컬 음성 가용성은 별도 검증 대상이다.
