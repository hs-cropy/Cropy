# CI 구현 계획

> 실행 방식: 현재 세션에서 직접 구현하고 독립 코드 리뷰 후 실제 Actions를 검증한다.

## 목표와 범위
현재 develop에서 새 GitHub Actions CI를 작성한다. 모든 PR과 develop/main push에서 frontend lint·Vitest·타입 검사·빌드, backend pytest를 실행한다. Windows·ML·E2E는 후속 범위다. PR #27은 참고 이력이며 복구하지 않는다.

## 작업 순서
- [x] 현재 테스트와 프론트 검사 실행, 실패 원인 확인
- [x] frontend/package.json의 typecheck 명령과 호환 가능한 lint 설정 정리
- [x] .github/workflows/ci.yml: 변경 감지, 병렬 검사, 캐시, 시간 제한, 이전 실행 취소
- [x] .github/scripts/ci-gate.mjs 및 회귀 테스트: 실패·취소·예상 밖 생략은 거부, 문서 변경은 의도된 생략 허용
- [x] 로컬 검사와 workflow 정적 검사, 독립 리뷰
- [x] 커밋 이름 확인 후 push, develop 대상 PR 및 실제 Actions 결과 확인
- [x] 검증 결과와 운영 제약을 reports에 기록

## 검토 초점
1. 문서 PR은 두 테스트를 생략해도 최종 검사는 실행되어야 한다.
2. 의존성·공통 설정·workflow 변경은 관련 전체 검사를 실행한다.
3. 변경 감지 실패나 예상하지 않은 skipped 상태를 성공으로 숨기지 않는다.
4. 취소된 필수 작업을 성공으로 처리하지 않는다.
5. 모든 대상 브랜치의 PR 및 병합 후 push를 검증한다.

## 운영 제약
GitHub API가 현재 비공개 저장소의 branch protection/rulesets에 요금제 제한 403을 반환했다. ci-required를 제공하되 강제 병합 차단 설정은 적용된 것으로 주장하지 않는다.
