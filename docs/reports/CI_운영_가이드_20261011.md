# CI 운영 가이드

## 구성
.github/workflows/ci.yml은 모든 대상 브랜치의 PR과 develop/main push에서 실행한다. 기존 #27은 복구하지 않고 현재 develop에 맞춰 새로 작성했다. 보안 업데이트는 별도 PR #71이다.

- frontend: Node 22, npm ci → lint → Vitest → typecheck → build.
- backend: Python 3.13, CPU requirements 설치 → pip check → pytest.
- PR은 경로 변경에 따라 영역 전체 검사를 실행하고, push/수동 실행은 두 영역 모두 실행한다.
- backend 및 ml 변경은 backend 검사, frontend 변경은 frontend 검사, .github·Compose·공통 Git/Docker 설정 변경은 두 검사 모두 실행한다.
- 문서만 변경한 PR은 두 영역 검사를 생략한다. changes와 ci-required는 계속 실행된다.
- ci-required는 변경 감지 실패, 검사 실패/취소, 실행해야 하는 작업의 생략을 실패 처리한다. 모든 필수 작업이 성공하거나 변경 없는 작업만 의도적으로 생략되어야 통과한다.
- PR별 이전 실행 취소(push·수동 실행은 run_id별 독립 그룹), npm/pip 캐시, 검사별 15분 제한, JUnit 결과 14일 보관.
- 워크플로는 contents:read, 변경 감지 작업만 pull-requests:read. 외부 Actions는 커밋 SHA로 고정하고 checkout 인증정보를 남기지 않는다.

## 로컬 명령
frontend: npm ci, npm run lint, npm test, npm run typecheck, npm run build. Node 22 최신 패치 권장(의존성 최소 22.13 이상).
backend: python -m pip install -r requirements.txt, python -m pip check, python -m pytest -q -rs.
최종 판정 회귀 검사: node --test .github/scripts/ci-gate.test.mjs.
워크플로 정적 검사: actionlint .github/workflows/ci.yml.

## 실패 확인
PR Checks에서 frontend/backend 로그를 먼저 확인하고, CI 실행의 Artifacts에서 JUnit 결과를 내려받는다. 설치나 lint 단계에서 실패하면 테스트가 실행되지 않아 결과 파일이 없을 수 있다. ci-required의 Actions summary에는 실행/생략/실패 결과가 표시된다.

## 적용 범위와 남은 작업
- 현재 GitHub API는 저장소 branch protection/rulesets에 요금제 제한 403을 반환한다. ci-required는 상태 검사이며 강제 병합 차단이 이미 설정된 것은 아니다. 기능 사용이 가능해지면 develop/main의 필수 검사로 ci-required를 등록한다.
- 기존 열린 PR에서 새 워크플로를 사용하려면 해당 PR 브랜치가 워크플로를 포함하도록 기준 브랜치를 갱신해야 한다.
- workflow_dispatch 버튼은 워크플로가 현재 기본 브랜치 develop에 병합된 뒤 사용할 수 있다.
- ML 테스트, Windows NTFS 권한 전용 작업, 미병합 오프라인/프로토타입 검사, Docker·브라우저 E2E는 후속 범위다. GPU학습과 실기기 검증을 통과한 것으로 간주하지 않는다.
- 보안 감사는 이 workflow에 무조건적인 전체차단으로 넣지 않았다. PR #71에서 운영 취약점은 정리했고 개발 도구 미패치 경고는 별도 관리한다.
