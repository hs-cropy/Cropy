## 구현

[PR #73](https://github.com/hs-cropy/Cropy/pull/73), 기준 develop.

- .github/scripts/package-preflight.mjs: 설치 전에 package.json과 package-lock.json을 읽어 JSON 문법과 최상위 객체 여부를 검사한다. lint/test/typecheck/build는 비어 있지 않은 명령 문자열이어야 한다. 누락 파일, 잘못된 JSON, 누락 스크립트는 파일/항목과 함께 실패로 보고한다.
- .github/workflows/ci.yml: frontend의 npm ci 직전에 검사한다. ci-required는 기존 최종 판정과 함께 사전 검사 회귀 테스트도 실행한다.
- npm ci의 의존성/lock 일치 검증을 유지한다. 사전 검사는 자동 복구 도구나 패키지 보안 검사 대체물이 아니다.
- 운영 가이드에 로컬 실행법과 병합 시 스크립트 보존 절차를 추가했다.

## #58 갱신

기존 head dc84d38에는 typecheck, 최신 Next/PostCSS 및 CI가 없었다. 먼저 기준 브랜치 fe/browser-offline을 병합해 검증된 패키지 수정과 CI를 가져왔다(a6dabf8). 이 단계에서 기준 브랜치와의 차이는 원래 배포 설정 3개 파일이었다.

이어서 최신 develop 7b2d739를 병합했다(5062bd9). package.json의 scripts 충돌은 test:offline, typecheck, test:prototype을 모두 보존해 해결했다. 의존성/lock은 이 두 번째 병합에서 바뀌지 않았다. develop에 있던 모바일 프로토타입 파일도 함께 포함되므로 최종 PR diff는 최초 3개 파일보다 크다.

#58의 PR 기준 브랜치는 기존 fe/browser-offline을 유지했다. #56은 fe/diagnosis-feedback으로 병합됐고, 그 병합이 최신 develop에 아직 포함되지 않은 상태였다. PR이 MERGED인지와 최종 develop에 코드가 들어갔는지는 별도로 확인해야 한다. 이번 작업에서 PR 병합이나 기준 브랜치 변경은 하지 않았다.
