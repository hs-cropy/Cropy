## 4. 과거 로그와 최신 상태의 차이

1. 기존 1절은 **9/8 당시 기록**으로 유지한다. 이후 변경을 과거 성과에 덮어쓰지 말고 날짜가 있는 추가 로그로 연결한다.
2. “테스트 27개”는 당시 수치다. 이번 backend 작업 트리 결과는 **183 passed, 1 skipped**이며 검증 환경을 함께 적는다.
3. “카메라 없음”, “ml/README 없음”, “이력 API 필터 없음”은 최신 작업 브랜치에서는 달라졌다. 아직 develop 미병합이므로 브랜치 상태를 병기한다.
4. 기존 96.2%/93.1%, 축소 val 96.23%, 작업자 분할 val 91.85%/92.48%는 분할·평가 조건이 다르다. 연속된 성능 하락/향상 추이로 나열하지 않는다.
5. 모델 파일은 Git에 없는 로컬 산출물이다. 로그의 체크포인트 경로만으로 팀원에게 배포된 것으로 표시하지 않는다. 해시와 별도 전달 위치가 필요하다.
6. “전체 라벨 조사 완료”와 “원천 이미지 전체 확보”는 다르다. 현재 작업 이미지 4,246장과 라벨 91,041개를 혼동하지 않는다.
7. LLM train 1,000/val 200/test 200, calibration 300~1,000은 **계획값**이다. CNN 성과로 LLM 학습 성과를 대신하지 않는다.
8. `backend`의 이전 백로그가 참조하는 LLM 계획은 현재 [ml 브랜치 문서](https://github.com/hs-cropy/Cropy/blob/ml/docs/LLM_FINETUNING_PLAN.md)에 있다. 두 PR 병합 전에는 브랜치 간 링크로 확인한다.
