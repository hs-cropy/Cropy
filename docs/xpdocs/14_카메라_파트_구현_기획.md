## 1. 목표와 범위

**목표**: 지금 `DiagnoseForm.tsx` 안에 있는 `<input type="file" capture>` 한 줄을, 라이브 프리뷰·촬영 가이드·리사이즈·재촬영 모드를 갖춘 독립 카메라 모듈로 바꾼다. 프론트(FE)는 컴포넌트 하나와 콜백 하나만 가져다 쓴다.

| 범위 안 (이번 스프린트 1~2) | 범위 밖 |
|---|---|
| getUserMedia 라이브 프리뷰, 후면 카메라 우선 | 단말(오렌지파이) 카메라 — 별도 `device/` |
| 셔터 → 캔버스 캡처 → JPEG File | 자동 셔터(프레임 안 초록 비율 판정) — 단말 단계 |
| 촬영 가이드 오버레이 (프레임, 밝기·흔들림 간이 체크) | 잎 검출 모델(온디바이스 세그멘테이션) |
| 클라이언트 리사이즈 (긴 변 1280px, JPEG 0.85) | 서버 측 전처리 |
| 파일 형식·크기 검증 (JPEG/PNG, 10MB) | HEIC 변환 (iOS는 브라우저가 JPEG로 주므로 제외) |
| 권한 거부·미지원 브라우저 → 파일 선택 폴백 | PWA 오프라인 캐시 |
| 재촬영 모드 (부위명 오버레이) | 음성 안내 연동 — S2-06에서 voice와 함께 |

## 2. 사용자 흐름 (M-01 → M-02)

```
[M-01 홈] 작물 칩 선택 → 촬영 카드 탭
    │
    ├─ getUserMedia 성공 ──► [M-02a 뷰파인더]
    │       라이브 프리뷰 + 가이드 프레임 + 밝기/흔들림 배지
    │       [갤러리] [● 셔터] [↺ 전환]
    │             │
    │             ▼ 셔터
    │       [M-02b 미리보기]  사진 크게 + 작물 표시
    │       [다시 찍기] [★ 진단하기]
    │             │
    │             ▼ 진단하기 → 리사이즈 → onCapture(file)
    │
    └─ 권한 거부 / 미지원 / 데스크톱 ──► 파일 선택 (지금 방식 그대로)
                                          → 검증 → 리사이즈 → onCapture(file)
```

재촬영 모드(M-05 → M-02 변형)는 같은 뷰파인더에 `regionLabel`("잎 뒷면")만 오버레이로 얹고, 셔터 후 미리보기 없이 바로 `onCapture`로 넘긴다. 확정 버튼을 하나 줄이는 대신 결과 화면에서 "다시 찍기"가 가능하므로 사용자 부담이 없다.

## 3. 폴더·파일 구조

팀 규칙대로 `frontend/src/features/camera/`는 CAM 소유. 이 폴더 밖(`DiagnoseForm.tsx`, `RecapturePanel.tsx`)을 고치는 PR은 FE(김민서)를 리뷰어로 지정한다.

```
frontend/src/features/camera/
├── index.ts                    # 외부 공개 표면: CameraCapture, useCamera, 타입만 export
├── CameraCapture.tsx           # 진입 컴포넌트. 상태 머신에 따라 아래 셋을 전환
├── CameraViewfinder.tsx        # <video> + 오버레이 + 셔터·갤러리·전환 버튼 (M-02a)
├── CapturePreview.tsx          # 캡처 결과 확인, 다시 찍기 / 진단하기 (M-02b)
├── CaptureGuideOverlay.tsx     # 잎 프레임 가이드 + 밝기/흔들림 배지 + 재촬영 부위명 (M02-F1)
├── FileFallback.tsx            # 권한 거부·미지원 시 파일 선택 UI (M01-F3, 예외)
├── hooks/
│   ├── useCamera.ts            # getUserMedia 열기/닫기, 후면 우선, 기기 전환, 권한 상태
│   ├── useFrameQuality.ts      # requestAnimationFrame으로 밝기·흔들림 간이 측정
│   └── useCaptureFrame.ts      # <video> → <canvas> → Blob(JPEG) → File
├── lib/
│   ├── resizeImage.ts          # 긴 변 1280px 리사이즈, EXIF 방향 보정, JPEG 0.85 (M02-F5)
│   ├── validateImage.ts        # MIME(JPEG/PNG)·10MB 검사, 오류 메시지 반환 (M02-F6)
│   ├── frameQuality.ts         # 순수 함수: ImageData → { brightness, sharpness } (테스트 대상)
│   └── cameraSupport.ts        # mediaDevices 존재·secure context·모바일 여부 판별
├── types.ts                    # CameraCaptureProps, CaptureMode, GuideState, CameraError
└── __tests__/
    ├── frameQuality.test.ts    # 밝기·선명도 계산 단위 테스트
    ├── resizeImage.test.ts     # 리사이즈 비율·방향 보정
    └── validateImage.test.ts   # 형식·크기 경계값
```

명명 규칙: 컴포넌트는 PascalCase `.tsx`, 훅은 `use` 접두 camelCase, 순수 로직은 `lib/`에 두어 브라우저 없이 테스트한다. UI 컴포넌트는 `lib/`만 import하고, 반대 방향 import는 금지.

## 4. 파트 간 계약 (CAM → FE)

기능명세서 9절의 계약을 구체화한 것. 이 인터페이스가 S1-07 산출물이며, 합의 후에는 `types.ts`에 그대로 박는다.

```ts
// features/camera/types.ts

export type CaptureMode = "diagnose" | "recapture";

export type GuideState = "good" | "dark" | "bright" | "blurry" | "idle";

export type CameraErrorCode =
  | "permission-denied"   // 사용자가 권한 거부
  | "not-supported"       // mediaDevices 없음, http 등 insecure context
  | "no-device"           // 카메라 장치 없음 (데스크톱)
  | "invalid-file"        // 형식·크기 검증 실패
  | "unknown";

export interface CameraCaptureProps {
  /** 캡처(또는 파일 선택)가 확정되어 리사이즈까지 끝난 File. FE는 이걸 그대로 API에 보낸다 */
  onCapture: (file: File, meta: { source: "camera" | "file"; width: number; height: number }) => void;
  /** 기본 "diagnose". "recapture"면 부위명 오버레이 + 미리보기 생략 */
  mode?: CaptureMode;
  /** recapture 모드에서 오버레이에 띄울 부위명 (예: "잎 뒷면") */
  regionLabel?: string;
  /** 미리보기 상단에 표시할 선택 작물명. 없으면 표시 안 함 */
  cropLabel?: string;
  /** 리사이즈 긴 변. 기본 1280 */
  maxLongEdge?: number;
  /** 카메라 실패 시 파일 선택으로 자동 전환. 기본 true */
  fallbackToFile?: boolean;
  /** 오류를 FE 토스트로 올리고 싶을 때. 미지정 시 컴포넌트 안에서 인라인 표시 */
  onError?: (code: CameraErrorCode, message: string) => void;
  /** 뷰파인더 열림/닫힘 통지. FE가 하단 탭 숨김 등에 사용 */
  onOpenChange?: (open: boolean) => void;
}
```

**FE 쪽 변경 최소화**: `DiagnoseForm`은 촬영 카드 `<label>`+`<input>` 블록을 `<CameraCapture cropLabel={...} onCapture={(file) => setFile(file)} />`로 바꾸고, `fileRef` 대신 `file` state를 둔다. `preview` objectURL 생성·해제도 카메라 모듈이 책임진다. 그 외 로직(진단 요청, 결과 표시)은 그대로.

`RecapturePanel`은 `<input>`을 `<CameraCapture mode="recapture" regionLabel={guidance.region} onCapture={handleRefine} />`로 교체.

## 5. 상태 머신 (CameraCapture 내부)

```
idle ──(마운트, 모바일·지원 확인)──► opening ──(스트림 획득)──► viewfinder
  │                                     │
  │                                     └─(거부/미지원/장치없음)──► fallback (FileFallback)
  │
viewfinder ──(셔터)──► captured ──(진단하기)──► resizing ──(완료)──► done → onCapture()
     ▲                    │
     └───(다시 찍기)───────┘
viewfinder ──(갤러리)──► fallback 과 동일 경로로 파일 검증 → resizing
```

- `viewfinder`에서 벗어날 때 반드시 `MediaStreamTrack.stop()` (배터리·카메라 LED).
- 페이지 `visibilitychange`로 백그라운드 전환 시 스트림을 닫고, 복귀 시 다시 연다.
- `recapture` 모드는 `captured`를 건너뛰고 `resizing`으로 직행.

## 6. 촬영 가이드 (M02-F1) 설계

간이 체크만 한다. 정확한 잎 검출은 범위 밖.

| 항목 | 측정 | 판정 | 안내 문구 |
|---|---|---|---|
| 밝기 | 프리뷰를 64×48로 축소해 평균 휘도 (0~255) | < 60 어두움, > 200 과다 노출 | "더 밝은 곳에서 찍어주세요" / "빛 반사를 피해주세요" |
| 흔들림 | 같은 축소 프레임의 라플라시안 분산 (선명도) | 임계 미만 2프레임 연속 | "잠시 멈춰주세요" |
| 프레임 | 화면 중앙 70% 영역에 둥근 사각 가이드 + 네 모서리 | 판정 없음(시각 안내만) | "잎 한 장이 테두리에 꽉 차게" |

- 측정 주기 250ms (`useFrameQuality`, rAF + 스로틀). 저사양 폰 배터리를 고려해 프리뷰 해상도가 아닌 축소 캔버스에서 계산.
- 배지는 `GuideState`로만 표현하고 문구·색은 디자인 토큰(signal-low/med)을 따른다. 판정이 나빠도 셔터는 막지 않는다(원칙 8 "되돌리기 제공").
- 임계값은 `frameQuality.ts` 상수로 두고, 실제 폰 3대(안드로이드 2, iOS 1)로 5주차에 보정.

## 7. 브라우저 호환 · 예외

| 상황 | 대응 |
|---|---|
| iOS Safari | `<video playsInline muted autoPlay>` 필수. `facingMode: { ideal: "environment" }`로 요청(exact는 실패 잦음). 캔버스 캡처 시 `toBlob("image/jpeg", 0.85)` |
| 안드로이드 Chrome | 기기 전환은 `enumerateDevices()` 후 `deviceId` 지정. 첫 호출은 권한 전이라 label이 비어 있으니 권한 획득 후 재조회 |
| http (LAN IP로 폰 테스트) | `getUserMedia`는 secure context에서만 동작. **개발 시 `next dev --experimental-https` 또는 ngrok** 사용. `cameraSupport.ts`에서 `window.isSecureContext`를 보고 즉시 폴백 |
| 데스크톱 | 웹캠 있으면 뷰파인더, 없으면 폴백. 발표 데모는 폰 화면 미러링 기준 |
| 권한 거부 | "카메라 권한이 필요해요" + [사진 선택] 버튼. 재요청 버튼은 두지 않음(브라우저가 두 번째 요청을 무시) |
| 파일 검증 실패 | "JPEG·PNG만 올릴 수 있어요" / "10MB 이하로 올려주세요" — `onError` 있으면 위임, 없으면 인라인 |
| EXIF 방향 | `createImageBitmap(file, { imageOrientation: "from-image" })`로 보정. 미지원 브라우저는 그대로 통과 |

## 9. 테스트 방법

| 층 | 방법 |
|---|---|
| `lib/` 순수 함수 | Vitest 단위 테스트 (`frameQuality`, `resizeImage`, `validateImage`). CI 워크플로(S1-09)에 `npm test` 추가 요청 → INF |
| 훅·컴포넌트 | 수동. 체크리스트: 권한 허용/거부, 후면·전면 전환, 백그라운드 복귀, 셔터 3회 연속, 갤러리 선택, 10MB 초과 파일, 세로/가로 회전 |
| 기기 매트릭스 | 안드로이드 Chrome 2대(저사양 1 포함), iPhone Safari 1대. 결과를 PR 본문 표로 남김 |
| 성능 | 프리뷰 중 `useFrameQuality` CPU 사용이 체감 발열 없이 5분 유지되는지 |

프론트에는 아직 테스트 러너가 없다. Vitest 도입은 `features/camera/` 범위에서 먼저 시작하고, 설정 파일(`vitest.config.ts`)은 루트라 FE와 합의 후 추가.

## 11. 완료 기준 (Definition of Done)

- 폰 브라우저에서 작물 선택 → 뷰파인더 → 셔터 → 미리보기 → 진단하기까지 파일 입력 없이 동작
