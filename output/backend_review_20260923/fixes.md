# 우선 취약점 수정 — 2026-09-23

정밀 검토의 B02·B09와 B03의 실행 시 검증을 우선 구현했다. 서비스 코드와 API 문서를 수정했고 실제 모델·운영 DB·시드 데이터는 변경하지 않았다. 기존 작업 트리의 사용자 수정도 유지했다.

## 반영

- B02: JPEG/PNG의 실제 형식으로 저장 확장자를 결정한다. 이미지 URL은 고정 이미지 MIME과 `nosniff`로 제공한다. 기존 `.html` 등 비허용 확장자 URL은 404이며 파일을 자동 삭제하지 않는다. 기존 `.jpg`·`.jpeg`·`.png`는 계속 제공한다.
- B09: 파일 구조 검사에 더해 전체 픽셀 디코딩을 확인한다. 손상 JPEG·PNG 체크섬 오류는 400, 픽셀 상한/Pillow 크기 보호 오류는 413을 반환한다. `MAX_IMAGE_PIXELS` 기본값은 40,000,000이며 양수만 설정할 수 있다. 원본 이미지 바이트·방향은 유지한다.
- B03: 빈 출력, 중복/비정수 ID, 비유한/범위 밖 점수, 미등록 클래스, 재촬영 클래스 집합 불일치 및 잘못된 보조 모델 출력을 차단한다. DB의 첫 병해를 선택하는 fallback을 제거했다. 출력 검증 실패 시 503, 새 진단 생성 없음, 기존 재촬영 결과 보존, 해당 요청의 새 파일만 정리한다.
- API_SPEC·ARCHITECTURE·환경변수 예시를 실제 동작에 맞췄다. 개발 Mock은 유지했다.

## 검증

- 업로드 보안 테스트 13개: 수정 전 실패 확인 후 통과. JPEG/PNG 형식 위장, 레거시 HTML, 정상 JPEG 제공, 손상 데이터, 픽셀 한도, PNG CRC 오류를 최초·재촬영 경로에서 확인.
- 모델 검증 테스트 34개: 서비스 경계 조건, 선택적 보조 모델·Mock 호환, API 503, 이력/파일 보존 확인. 초기 결함 검사는 28개 실패를 확인한 뒤 구현했다.
- 전체 백엔드: `backend/.venv/Scripts/python.exe -m pytest -q -p no:cacheprovider` (backend 디렉터리에서 `.venv/Scripts/python.exe` 사용), **74 passed in 16.81s**.
- 독립 코드 리뷰에서 발견된 PNG CRC 예외 누락도 회귀 테스트와 함께 수정했다. 통합 리뷰의 추가 차단 사항 없음.
- 배포·실제 브라우저·Orange Pi 검증은 하지 않았다. 커밋/푸시는 하지 않았다.

## 남은 우선 작업

요청 수신 전 전체 바이트 제한(B08), 모델 기동 시 체크포인트 계약 검증 및 운영 Mock 분리(B03 나머지·B05), 농약 사용 조건 분리와 동기화 부분 실패 처리(B01·B04), 일반 추론/DB 오류 및 교체 이미지 정리(B10 나머지)는 후속 작업이다.

입력 허용 형식은 명세대로 JPEG/PNG로 제한했다. 과거 GIF/WebP 등 기타 확장자로 저장된 파일은 이번 정적 제공 정책에서 제외되므로, 그런 이력을 계속 표시해야 한다면 원본을 보존한 별도 이전 작업이 필요하다.

기존 [report.md](report.md)·[evidence.json](evidence.json)·[probe.py](probe.py)는 수정 전 분석 기록이다. probe.py는 당시의 취약 동작을 관찰하는 스크립트라 현재 코드의 통과 검증으로 사용하지 않는다. 수정 후 회귀 검사는 backend/tests를 사용한다.
