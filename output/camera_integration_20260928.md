# 카메라 브랜치 통합 검증 기록

- 확인일: 2026-09-28
- 대상: 현재 로컬 작업본 + `fe/camera`의 `28c755a544e0a0b900b5120d3bee41203cc1c461`
- 수행: 김헌영 작업 맥락에서 팀원 카메라 코드 리뷰 및 로컬 통합 검증
- 범위: 별도 테스트 복제본. 본 작업 브랜치에 카메라 기능을 병합한 기록이 아니다.

## 실행 및 확인 결과

- 프론트엔드 3002, 백엔드 8002 포트에서 별도 DB·업로드 폴더로 실행하였다.
- 기존 모델을 읽어 로드했으며 health에서 `model_loaded=true`를 확인하였다.
- 가상 카메라로 라이브 미리보기 → JPEG 셔터 → 폼 미리보기 → 실제 모델 진단 → 결과 → 이력·상세 조회를 확인하였다.
- 타입 검사와 ESLint를 통과하였다.
- API 테스트 14개를 통과하였다. 무체크포인트 시연 테스트에는 mock 허용 설정을 적용했으며 실행 서버에서는 mock을 차단하였다.
- 합성 카메라 영상은 연결 검증용이다. 해당 결과는 병해 진단 정확도의 근거가 아니다.

## 코드 리뷰 결과

1. `/camera` 개발 페이지의 셔터·갤러리는 연결되지 않았다. 담당자의 후속 작업 예정 사항이다.
2. 뷰파인더는 `object-cover`, 저장은 전체 영상 프레임이라 비율에 따라 촬영 범위가 다르다. 가상 장치의 원본 1280×720을 480×448 화면에 표시할 때 원본 기준 중앙 약 771×720만 보였다.
3. 카메라를 열고 Tab 네 번 이동하면 배경의 자동 감지 버튼으로 포커스가 빠졌다.
4. 재생 실패를 주입해도 셔터가 활성화되었다. `play()` 오류를 무시하고 streaming으로 전환하는 코드가 원인이다.
5. `toBlob()`이 null을 반환하도록 실패를 주입했을 때 사용자 오류 안내 없이 오버레이가 유지되었다.
6. 닫기 후 트랙이 ended로 종료되고 body 스크롤 잠금이 복원됨을 확인하였다.

위 카메라 문제는 확인·기록했으며 이번 작업에서 수정하지 않았다. 실제 웹캠·모바일 권한·전후면 전환·백그라운드 복귀는 실기기 검증이 남아 있다. 임시 복제본과 실행 로그는 `tmp/`에 두고 버전 관리에서 제외한다.
