# 주요 오분류 42장 검토

## 범위와 산출물

고정된 val 예측 중 무검은무늬병↔무노균병 28장, 배추노균병→정상 14장을 검토했다. 원본 파일에서 만든 미리보기 42장을 모두 육안 확인하고 전체 라벨 JSON과 파일 크기·클래스 코드를 대조했다. 원본 해상도에서 병명을 재판정한 작업은 아니다.

- `index.html`: 사진 42장과 원본 링크. 브라우저에서 열고 이미지를 클릭하면 원본으로 이동한다.
- `review.csv`: 사진별 예측, 점수, 작업자, 날짜, 원본 경로, 라벨 코드, bbox 검사, 검토 상태.
- `worker_stats.csv`: 해당 클래스 val 전체를 분모로 한 작업자별 오류율.
- `contact_1.jpg`~`contact_5.jpg`: 전체 사진 모음.

## 라벨·파일 대조

42장 모두 기존 클래스와 라벨 코드가 일치한다. 이는 메타데이터 일관성 확인이며 실제 병명이 정확하다는 독립 검증은 아니다. bbox 좌표는 실제 이미지 범위 안에 있다. bbox 면적은 대상 영역 면적이며 병징 크기로 해석하지 않는다.

검토 번호 9~14의 6장은 라벨 width/height가 0/0이다. 실제 이미지는 4032×3024로 정상적으로 열린다. 현재 전체 이미지 분류 학습은 이 라벨 치수를 사용하지 않으므로 이것이 오분류 원인이라는 근거는 없다. 향후 bbox 전처리에서는 실제 이미지 치수를 기준으로 검사해야 한다. 라벨과 이미지 파일은 수정하지 않았다.

## 사진에서 관찰한 점

- 무 병해(#1~28): 잎 앞·뒷면과 촬영 거리 차이, 손·주변 잎·토양 배경, 작은 갈색 부위·구멍·잎 가장자리 변색 등이 보인다. #7~8, #15~16, #23~27에는 강한 빛이나 그림자가 있다. 이 관찰만으로 두 병명을 구분하거나 라벨 오류를 확정할 수 없다.
- #26~27은 같은 작업자·날짜이고 구도가 매우 유사하다. 바이트 중복 제거 후에도 유사 사진이 남을 수 있음을 보여주는 검토 후보다. 동일 개체 여부는 미확인이고 두 사진 모두 val이므로 이 사례 자체가 분할 누수를 뜻하지 않는다.
- 배추노균병(#29~42): 여러 잎이나 포기 전체가 들어간 사진과 잎 근접 사진이 섞여 있다. 일부 잎에 노란 부위가 보이지만 축소 미리보기만으로 병징의 충분성을 판단하기 어렵다. #42는 밝은 부분이 강하게 보인다. 정상으로 예측했다는 이유로 정상 라벨로 바꾸지 않는다.
- 무 병해 #17은 잘못된 예측 점수가 약 0.97이다. 모델 점수가 높아도 정답을 보장하지 않는다.

## 다음 실험 판단

현재 대조에서 자동으로 라벨을 변경할 근거는 찾지 못했다. 조명·작은 시각 단서가 원인이라는 것은 검증할 가설이며, 정답 사진과의 체계적 비교 없이 인과관계를 확정하지 않는다.

다음은 고정 분할을 유지한 256 입력 대조 실험이다. ImageNet 초기화·seed·20 epoch·일반 샘플링·선택 지표는 224와 동일하게 유지한다. 정확도 91.85%, macro F1 0.9035와 클래스별 재현율을 비교하고, 이번 42장뿐 아니라 val 전체의 새 오류도 함께 본다. 256 향상은 아직 확인되지 않았다. bbox 크롭이나 샘플링 변경을 동시에 적용하지 않는다. test는 계속 보류한다.
