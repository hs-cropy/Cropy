# 256 모델 오류 59장 원인 검토

검토일: 2026-09-28 · 대상: 작업자 분리 ResNet50 / 256 / seed 42 / val 785장

## 1. 결론

**오류 59장 전부의 파일·라벨 대응과 시각 검토를 완료했다. 원인 하나로 설명할 증거는 없으며, 무 두 병해의 구분과 병해→정상 오류를 우선 추적해야 한다.** 새 오류 12장 중 9장이 무 병해 상호 혼동이다. 256 확대만으로 취약한 구분이 해결되지는 않았다.

사진에서 작은 시각 단서·대상 부위 차이·명암·복잡한 배경을 관찰했지만 정답 사례에도 같은 특징이 있었다. 따라서 이를 확정 원인으로 세거나 “사진이 어두워서 틀렸다”라고 단정하지 않는다. 고추탄저병에는 **열매 사진**이 포함되어 있어 모든 클래스를 잎 크롭으로 처리하자는 제안도 수정해야 한다.

이번 작업은 저장된 예측 결과와 원본 파일·라벨 캐시의 분석이다. 모델 재추론·재학습·서비스 변경·라벨 수정은 수행하지 않았다. 보류된 새 분할 test 722장을 평가하거나 검토하지 않았다.

## 2. 검토 범위와 재현

- [예측 비교 CSV](../group256_analysis_20260924/paired_predictions.csv) 785개와 현재 manifest의 val 785개를 대조하고, 혼동행렬을 재계산해 저장 지표와 일치함을 확인했다.
- manifest SHA256: `d0fda6ef2e51b7ea1a201941e10dadea2f8e6b33eca785735b3d0dec58620e72`.
- 오류 59장과 정답 대조군 18장 모두 로컬 원본을 열어 표시용 이미지를 만들고 파일 SHA256을 manifest와 대조했다.
- 전 표본의 **원본 비율 미리보기와 256×256 입력 미리보기**를 확인했다. E06·E30·E53·E59는 원본 파일을 별도로 크게 열어 추가 검토했다. 화면 표시는 축소될 수 있으며 원본 모든 픽셀을 판독하거나 병리학적 진단을 한 것은 아니다.
- 정답 대조군은 오류가 발생한 클래스·작업자 조합 9개에서 경로 SHA256 정렬 첫 2장씩 선택했다. 특징을 보고 고른 표본은 아니지만 소규모 탐색용 대조군이며 전체 정답 분포의 대표성을 보장하지 않는다.
- 라벨은 기존 전체 라벨 조사에서 추출한 `matched_labels.json` 캐시를 사용했다. val 785개 모두 crop/disease 코드와 클래스의 일치를 독립 대조했다. 이는 **메타데이터 일치**이지 실제 병명 라벨의 정확성 검증은 아니다.
- 원본 경로의 `data/dataset/train`, `val`, `test`는 과거 저장 위치다. 이번 실험의 분할은 `candidate_split`/`bundle_path`를 기준으로 하며, 과거 폴더명이 새 test 접근을 의미하지 않는다.

재현: 저장소 루트에서 `python output/colab/error_review_256_20260928/prepare.py` 실행 후 `python output/colab/error_review_256_20260928/finalize.py`. Pillow와 로컬 원본 이미지·manifest·라벨 캐시가 필요하다. `visual_notes.json`은 이번 시각 관찰 기록이며 자동 원인 판정 결과가 아니다. 첫 명령은 준비 산출물을 갱신하므로 두 번째 명령까지 실행해야 주석이 반영된다.

## 7. 다음 실험 제안 — 아직 실행하지 않음

1. **라벨·대상 부위 기준 확인:** E59와 무 혼동 표본을 검수하고, 고추 열매/잎·배추 잎 기부/잎면 등 클래스별 진단 대상 기준을 정리한다. 모델 예측을 정답으로 삼아 라벨을 바꾸지 않는다.
2. **학습 데이터 커버리지 조사:** train에서 무 두 병해의 촬영면·국소 변화·명암·작업자 분포를 조사한다. 이번에는 val만 검토했으므로 train에 어떤 특징이 부족한지 아직 결론 내리지 않는다.
3. **입력 대조 실험:** 256 후보를 고정하고 기존 전체 입력과 비율 유지 패딩 또는 대상 영역 입력 중 한 가지 변경만 비교한다. 이미 본 59장만 평가하지 말고 val 전체에서 새 오류·클래스별 재현율도 본다. 모델 재학습 없는 입력 변경은 분포 변화 영향을 포함한 진단 실험이다.
4. **bbox 실험의 한계 관리:** 정답 bbox는 배포 시 주어지지 않는다. 사용한다면 대상 영역의 정보 유무를 보는 참고 실험으로 표시하고, 실제 카메라/탐지 경로의 bbox와 별도 검증한다. bbox 면적을 병징 면적으로 해석하지 않는다.
5. **선정 조건 고정 후 재검증:** 유망한 변경만 여러 seed로 확인하고, 후보를 확정한 뒤 보류 test를 사용한다. 목표는 전체 정확도와 함께 무 혼동 31건·병해→정상 22건 감소이며 개선을 보장하지 않는다.
