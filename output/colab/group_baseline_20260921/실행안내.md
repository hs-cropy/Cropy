# cropy 작업자 분리 기준선 — Colab 실행

## 준비한 파일

- 노트북: `ml/cropy_group_baseline.ipynb`
- 번들: `output/colab/group_baseline_20260921/cropy_group_baseline_bundle.zip` (약 7.75GB)
- 구성 및 검증 결과: 같은 폴더의 `bundle_info.json`, `manifest.csv`
- 재생성 스크립트: `ml/pack_group_baseline.py` (기존 ZIP이 있으면 덮어쓰지 않고 중단)
- 학습 스크립트: `ml/train_group_baseline.py`

## 실행 순서

1. Google Drive의 `내 드라이브/cropy` 폴더에 번들 ZIP을 업로드한다. ZIP 이름은 그대로 유지한다.
2. Colab에서 **새 노트북 `cropy_group_baseline.ipynb`**를 연다. 기존 week3 노트북을 실행하는 것이 아니다.
3. `런타임 → 런타임 유형 변경 → GPU`를 선택한다.
4. 1번 셀에서 Drive 연결을 허용한다. ZIP 해시, 원본 이미지 해시, 작업자 분리, 이미지 수를 검증하고 압축을 푼다. 이미지 4,235장과 train 2,728 / val 785 / test 722가 출력되어야 한다.
5. 2번 셀로 20 epoch 학습한다. 처음에는 ImageNet 가중치를 다운로드한다. 인터넷 연결이 필요하다. 새 cropy 모델을 학습하며 기존 cropy 체크포인트는 사용하지 않는다.
6. 3번 셀에서 val 결과를 확인한다. 4번 셀에서 결과 ZIP을 받아 로컬 프로젝트에 넣는다.
7. **5번 test 셀은 기본값 False로 둔다.** 224/256 등 모델과 설정 선택을 마친 뒤 최종 평가에 사용한다.

학습 결과는 `내 드라이브/cropy/results/<실행시각>`에 저장된다. Colab 세션이 끊겨도 저장된 최고 모델과 epoch 기록은 남는다. 자동 이어학습은 지원하지 않으며 처음부터 다시 시작하려면 1번 셀부터 새 실행 폴더를 만든다. 같은 결과 폴더를 덮어쓰는 학습은 중단된다. GPU 메모리 부족 시 batch를 16으로 낮춰 새 실행을 시작할 수 있으며 config에 기록된다. 소요 시간은 GPU와 원본 디코딩 속도에 따라 달라 아직 측정하지 않았다.

## 고정한 실험 조건

- 작업자별 그룹 분리, 동일 바이트 이미지 중복 제거. 원본 파일은 수정·삭제하지 않았다.
- ResNet50, ImageNet `IMAGENET1K_V2`에서 시작, 입력 224, seed 42.
- 일반 샘플링, AdamW lr 0.0001 / weight decay 0.0001, label smoothing 0.1, cosine schedule, 20 epoch.
- 기존 `train.py`의 증강 및 평가 전처리를 재사용한다. 원본 ZIP에는 리사이즈나 JPEG 재인코딩을 적용하지 않는다. 모델 입력 시에만 전처리한다.
- 최고 val 정확도로 체크포인트를 선택한다. 동률은 앞선 epoch를 유지한다. macro F1과 클래스별 재현율도 함께 기록한다.
- `history.jsonl`: 모든 epoch 지표. `val_metrics.json`, `val_predictions.csv`: 선택 모델의 검증 결과. `config.json`: 환경과 학습 조건. `best_model.pth`: 선택 모델.

## 해석할 때 주의할 점

새 val/test에는 과거 train 이미지가 포함되어 있어 기존 cropy 가중치로 이어학습하면 독립 평가가 아니다. 과거 val 96.23%와 이번 수치를 직접 비교하지 않는다. 과거 가중치 파일은 번들에서 제외했다.

작업자는 개체·농장 ID가 아니다. 다른 작업자가 같은 개체를 찍었거나 유사 이미지가 남았을 가능성까지 배제한 것은 아니다. 무노균병은 전체 작업자가 5명이며 새 train 3명 / val 1명 / test 1명에 불과하므로 성능을 넓게 일반화하지 않는다.

**현재 상태: 번들·노트북 준비 및 로컬 실행 점검. Colab GPU 학습과 새 모델 성능 확인은 아직 수행 전이다.**
