# 로컬 원천 메타데이터 조사 — 2026-09-18

## 결론

로컬 자료에는 날짜·지역 코드·작물·병해 등의 라벨은 있지만, 개체/농장/촬영 세션을 확정할 명시적 식별 필드나 코드 설명서가 없다. **현재 자료만으로 개체 독립적인 새 분할을 확정할 수 없다.** 기존 파일과 분할은 변경하지 않았다.

## 조사 범위와 연결률

- `data/01.고추`, `data/02.무`, `data/03.배추`에서 JSON 360개 확인: 작물별 120개, 전체 정상 180개·질병 180개. 파싱 오류 없음.
- `description.image`의 확장자를 제외한 파일명으로 현재 dataset에 연결했다. 대소문자 정규화 후 중복 매칭 없음.
- 현재 이미지 4,246장 중 128장(약 3.01%)만 연결된다. 라벨 JSON 360개 전체가 현재 학습 데이터에 대응하는 것은 아니다.
- 연결된 128장의 파일명 병해·작물·부위·생육·위험도 토큰과 JSON 값은 모두 일치했고, 날짜 토큰도 JSON 날짜와 일치했다.

## 실제 JSON 필드

| 필드 | 관찰 결과 | 분할에 활용 가능한 범위 |
|---|---|---|
| description.image | 이미지 파일명 | 파일 연결 |
| description.date | 날짜 53종 | 날짜 단위 분석 가능. 개체/세션 ID는 아님 |
| description.worker | 360개 모두 빈 문자열 | 그룹 식별에 사용 불가 |
| description.region | null 180개, 코드 1·7·8·9 | 지역 코드 차이는 확인 가능. 코드 의미와 농장 대응은 미확인 |
| description.width / height | 이미지 크기, height=0인 라벨 10개 | 실제 이미지와 대조 후 활용 필요 |
| description.task / type | task=79, type=0 또는 1 | 작업·유형 코드 |
| annotations.disease / crop / area / grow / risk | 정수 코드 | 클래스/조건 확인. 개체 ID는 아님 |
| annotations.points | 모든 JSON에 좌표 객체 1개, xtl/ytl/xbr/ybr | 사각형 좌표 제공. 대상이 병반인지 작물/잎인지 로컬 설명만으로 확정 불가 |

예시 파일명의 `2852e`, `5389e`, `c14` 등 날짜 앞 코드는 JSON에 독립 필드로 설명되지 않는다. 이를 농장·촬영자·개체 ID로 단정하지 않는다. 정상 파일명의 `S01` 등 접미 코드도 정의를 확인하지 못했다.

연결된 부분집합에서 `(작물 코드, 날짜 앞 코드, 날짜)` 조합은 68개이고, 이 중 19개가 여러 분할에 걸친다. 이는 **파일명 기반 그룹 후보**이며 동일 개체가 분할을 넘었다는 확정 증거는 아니다.

## 다음 작업

1. 데이터 제공처의 파일명 규칙·라벨 정의 문서와 현재 이미지에 대응하는 전체 라벨을 확보한다. 확인 대상은 날짜 앞 코드, 정상 데이터의 S01 등 코드, region 정의, points 대상이다.
2. 의미가 확인된 개체/농장/촬영 그룹과 원본 중복 해시를 함께 사용해 새 분할을 설계한다. 날짜가 달라도 원본 해시가 같았던 중복이 있으므로 날짜 기준만으로는 부족하다.
3. 정의를 확보하지 못하면 파일명 그룹은 보수적인 실험 가정으로 명시하고, 개체 독립 평가가 검증됐다고 표현하지 않는다.
4. 새 분할에서 224 기준선과 256 입력 실험을 진행한다. 기존 cropy 가중치의 학습 이력을 고려해 새 평가 이미지가 노출되지 않도록 하며, 필요한 경우 ImageNet 가중치부터 학습한다.
