예시: 다음 두 사진은 이름의 작업자 코드와 일부 토큰이 다르지만 내용이 동일하다.

- Training: `train고추질병원천데이터.tar` 안의 `V006_79_1_01_01_01_13_2_1553bb_20200916_16.jpg`

따라서 작업자 코드만으로 분리하더라도 실제 이미지 해시 중복을 함께 검사해야 한다. 이름 차이의 원인이나 라벨 적절성은 이번 이미지 검사만으로 확정하지 않았다.

## 검사 방법과 검증

1. TAR 내부 ZIP 분할 조각의 바이트 위치가 연속인지 확인하고, 원본 파일 위에서 논리적으로 연결해 읽었다. 대용량 원본을 풀거나 다시 저장하지 않았다.
2. ZIP의 모든 이미지 항목을 끝까지 읽어 CRC를 검증했다.
3. Pillow 12.3.0의 `verify()`와 재열기 후 `load()`로 이미지 구조와 전체 디코딩을 검사했다. 잘린 이미지 허용 옵션은 껐다.
4. 이미지 파일 전체의 SHA-256을 계산했다.
5. EXIF 방향을 적용하고 RGB로 변환한 뒤 크기와 전체 픽셀로 두 번째 SHA-256을 계산했다.
6. 모든 해시를 모아 분할 간·분할 내부 중복을 분리 집계했다.
7. 최종 CSV의 36,811개 경로가 고유하며, 모든 행의 검사 상태가 정상이고 두 해시가 존재함을 재확인했다. 두 방식의 중복 그룹도 동일함을 확인했다.

본 검사에서 손상이 발견되지 않았다는 뜻이며, 정답 라벨·병징 가시성·사진의 진단 적합성까지 검증한 것은 아니다. 회전·크롭·밝기 변화 등으로 픽셀이 달라진 유사 사진, 연속 촬영, 동일 개체·농장 중복은 별도 검사가 필요하다. 모델 학습 및 정확도 평가는 실행하지 않았다.

## 학습 전 권고

원본 압축파일은 그대로 보존하고, 중복 처리 결정은 별도의 학습 목록에 반영한다.

- 공식 Validation을 유지한다면, 분할 간 중복 40쌍의 Training 쪽 사진을 학습 목록에서 제외하는 방안을 검토한다.
- 각 분할 내부의 동일 이미지도 한 장만 유지하되, 정답 라벨이 다르면 임의 선택 전에 검토한다.
- 후속 작업에서 위 방식을 [중복 제거 목록](../../data/full/manifests/deduplicated_v1/README.md)에 적용했다. Training 32,513장, Validation 4,070장, 총 36,583장을 유지하고 228장은 목록에서 제외했다. 원본 압축파일은 보존했다.
- 중복 정리 후에도 Validation을 반복적인 모델 선택에 사용한다면 독립적인 최종 test 설계가 필요하다. 기존 실험 자료와의 중복도 분할 확정 시 함께 고려해야 한다.
