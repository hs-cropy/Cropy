작성일: 2026-10-02

## 결과

중복 제거 목록의 이미지 **36,583장**을 원본 크기·바이트 그대로 추출하고, 대응하는 JSON 라벨 **36,583개**를 연결했다. 공식 Training 32,513장, Validation 4,070장을 유지했다. 원본 압축파일과 기존 실험 데이터는 변경하지 않았다.

## 확인한 사항

- 공식 분할과 이미지 이름을 기준으로 36,583장 모두 라벨이 정확히 1개씩 연결된다.
- 파일명과 라벨의 작물·병해·부위·생육·위험도·정상/질병 코드가 일치한다.
- 추출 시 ZIP CRC와 이미지 SHA-256을 확인했다.
- 추출 후 모든 이미지와 라벨을 다시 읽어 SHA-256을 대조했다. 누락·추가 파일, 이미지/라벨 해시 불일치, 클래스 불일치는 모두 0건이다.
- 최종 목록의 바이트 해시 중복은 0건이다. 기존 전수 검사에서 얻은 픽셀 해시도 중복 0건이며, 추출 이미지가 그 검사 대상과 동일 바이트임을 확인했다.
- 기존 `ml/train.py`의 이미지 변환과 torchvision ImageFolder로 두 분할을 읽었다. 클래스 순서 0~8이 일치하고, 각 분할의 클래스별 1장씩 총 18장을 변환해 `(3, 224, 224)` 형태와 유효한 수치를 확인했다. 모든 이미지의 변환을 다시 실행한 검사는 아니다.

## 메타데이터 유의사항

날짜 불일치 29건(Training 25건, Validation 4건)은 원본 라벨의 날짜가 비어 있다. 작물·질병 분류 라벨은 연결되므로 이미지는 유지하고 날짜를 임의로 수정하지 않았다. [날짜 문제 목록](date_metadata_issues.csv)을 날짜 기반 분할·분석 시 참고해야 한다.

이번 검사는 파일·라벨 연결의 구조적 검증이다. 사진을 보고 정답이 맞는지 판단하는 육안 검수나 유사 사진·동일 개체·농장 간 독립성 검증은 포함하지 않는다.

## 다음 학습에 사용할 경로

프로젝트 루트에서 기존 학습 스크립트의 데이터 경로를 다음과 같이 지정한다.

```text
--data-dir data/full/prepared_deduplicated_v1/images
```

정상 이미지와 질병 이미지의 수 차이가 크므로, 균형 샘플링 설정과 클래스별 재현율·Macro F1을 함께 검토한다. 학습 증강은 기존 train 변환에서 적용 가능하다.

현재 확인한 실행 환경은 `backend/.venv`의 PyTorch 2.12.1+cpu, torchvision 0.27.1+cpu이며 CUDA를 사용할 수 없다. 이번 작업은 데이터 준비와 로더 점검까지이며 시험 학습·본 학습·성능 평가는 실행하지 않았다.

별도 최종 test 분할은 만들지 않았다. 과거 실험 데이터가 공식 두 분할과 섞여 있었으므로 기존 체크포인트를 그대로 평가한 수치를 독립적인 최종 성능으로 해석해서는 안 된다. 본 실험 전에 최종 평가 설계를 확정해야 한다.
