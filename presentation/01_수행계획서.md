## 2. 프로젝트 개요

cropy는 고추·무·배추 사진을 분석해 병해 후보와 관련 정보를 제공하고, 판단이 어려운 경우 추가 촬영을 안내하는 서비스다. 모바일 웹앱을 먼저 구현·검증하고, 이후 Orange Pi 5 Plus에서 인터넷 없이 진단과 음성 안내를 수행하는 단말로 확장한다.

현재 분류 범위는 병해 6종과 정상 3종, 총 9개 클래스다. 고추탄저병·고추흰가루병·무검은무늬병·무노균병·배추검은썩음병·배추노균병 및 작물별 정상 상태를 다룬다. 해충이나 모든 작물의 질병을 포괄하는 모델은 아니다.

사용 흐름은 **작물 선택 → 사진 입력 → 진단 후보 확인 → 필요 시 재촬영 → 관련 정보 확인 → 이력 저장**으로 구성한다. 농약 사용 조건은 검증된 정보만 표시하고, 근거가 없으면 정보 부족을 안내한다.

## 3. 추진 배경

### 3.1 해결하려는 문제

- 비슷한 병징이 나타나면 사진 한 장의 분류 결과만으로 사용자가 다음 행동을 결정하기 어렵다.
- 병해 후보를 확인한 뒤에도 관련 정보와 방제 정보를 따로 찾아야 하는 부담이 있다.
- 농작업 중 화면 조작과 긴 설명을 읽는 부담을 줄일 수 있는 큰 글씨·단순한 동선·음성 안내가 필요하다.
- 통신이 불안정한 환경에서도 핵심 진단 기능을 사용할 수 있는 구성을 목표로 한다.

위 항목은 기획에서 설정한 사용자 문제와 설계 가설이다. 사용자 조사나 현장 실증을 완료했다는 의미는 아니다.

### 3.2 작업 과정에서 확인한 필요성

모델 평가에서 무검은무늬병과 무노균병 간 혼동이 반복되었다. 같은 검증 세트에서 입력 크기를 224에서 256으로 변경했을 때 전체 정답은 5장 늘었지만, 무 두 병해 간 혼동은 28건에서 31건으로 늘었다. 따라서 전체 정확도뿐 아니라 취약 클래스와 촬영 조건을 함께 살펴보는 접근이 필요하다.

9월 29일 학습 이미지 검토에서는 두 병해 모두 앞면·뒷면 추정 사진이 존재함을 확인했다. 혼동의 원인을 특정 촬영면의 부재로 단정하지 않고, 병징 가시성·표본 다양성·라벨 적절성을 전문가 검수로 확인할 계획이다.

## 4. 목표 및 내용

### 4.1 개발 목표와 현재 상태

| 개발 목표 | 현재 확보한 결과 | 남은 완료 조건 |
|---|---|---|
| 9클래스 CNN 진단, 최종 test 정확도 90% 이상 목표 | ResNet50 학습·평가 코드, 작업자 분리 val 기준 224 모델 91.85%, 256 후보 92.48% | 후보 확정 후 독립 test 평가 및 현장 검증 |
| 추가 촬영을 통한 재확인 | 재촬영 API·결과 갱신·이력 보존 코드 | 같은 사례의 단일 사진 대비 효과와 사용자 부담 측정 |
| 모바일 웹앱 | 사진 업로드·결과·이력·큰 글씨, 진단 출처·작물 불일치 안내 | 카메라 브랜치 통합, 실제 휴대폰 촬영·예외 흐름 검증 |
| 근거가 있는 농약 정보 연결 | 제품과 작물·병해별 사용 조건 분리, 미검증 조건 숨김, 동기화 로직 | 공식 데이터 갱신·검수와 서비스 반영 확인 |
| 오프라인 음성 단말 | Orange Pi 5 Plus 이전 절차와 역할별 백로그 | 보드 실행·CPU 추론 기준선·음성 연결·오프라인 복구 검증 |
| LLM 설명과 후속 질문 | 역할·입력 근거·학습 데이터·평가 계획 | 검수 데이터 구축, 기본 모델 평가, 보드 호환성 확인 |

위 정확도는 **검증 세트(val) 수치**다. 새로운 작업자 분할의 최종 test 목표 달성 여부는 아직 판정하지 않았다. 256 모델은 비교 후보이며 서비스 모델 교체 실적이 아니다.

### 4.2 시스템 구성

```text
[현재 웹 경로]
사진 업로드 → Next.js 화면 → FastAPI → ResNet50 분류
                                    ├ 병해·검증된 농약 정보 조회
                                    └ SQLite 진단·재촬영 이력 저장

[추가할 단말·음성 경로]
카메라 / 음성 입력 → 보드 내부 진단 서비스
                  → 진단 결과·검증된 DB 정보를 LLM에 제공
                  → 쉬운 한국어 설명 → 음성 출력
```

현재 주요 기술은 Next.js 15·TypeScript·Tailwind CSS, FastAPI·SQLAlchemy·SQLite, PyTorch·ResNet50이다. 단말은 Orange Pi 5 Plus 16GB를 목표로 한다. CNN은 CPU 실행을 먼저 확인하고, 측정 결과에 따라 ONNX·RKNN 전환 필요성을 판단한다.

LLM은 사진의 병명을 새로 판단하는 대신 CNN 결과와 검증된 DB 내용을 설명한다. Qwen3.5-2B는 기존 계획의 우선 후보이며, 제공받는 RKLLM 도구와 보드에서의 호환성 확인 후 확정한다. 기본 모델의 반복 실패가 확인될 때 파인튜닝을 검토한다.

### 4.5 평가 및 완료 기준

1. **기능:** 실제 가중치를 로드한 상태에서 진단·재촬영·이력 조회가 연결된다.
2. **모델:** 고정된 분할에서 정확도·Macro F1·클래스별 재현율을 비교하고, 후보 확정 후 test를 평가한다.
3. **재촬영:** 동일 사례의 전후 결과를 비교해 효과와 추가 촬영 부담을 확인한다.
4. **단말:** 초기 CNN 목표는 전처리 포함 단건 1초 이내이며 미측정 목표다. 첫 로드·예열 후 중앙값·p95·메모리·온도를 기록한다.
5. **안정성:** 30회 진단·30분 반복 운용, 인터넷 차단·재부팅·이력 보존을 검증한다.
6. **설명:** LLM이 병명·농약명·수치를 임의로 만들지 않는지 확인하고 실패 시 템플릿 안내로 복귀한다.

## 5. 기대효과

- 사진 입력부터 결과와 관련 정보 확인까지의 흐름을 단순화한다.
- 불확실한 결과에 추가 관찰 행동을 제시해 사용자의 판단을 돕는다.
- 검증된 정보와 미확인 정보를 구분해 결과를 과도하게 신뢰하는 문제를 줄이는 방향으로 설계한다.
- 큰 글씨와 음성 안내, 오프라인 실행으로 현장 접근성을 높인다.
- 사진·모델 버전·재촬영 결과가 남는 이력으로 후속 상담과 오류 분석을 지원한다.

이는 기대효과이며 수확량 증가·비용 절감·진단 개선 효과를 현장에서 입증한 실적은 아니다.
