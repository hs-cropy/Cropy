## 1. 3주차 주간보고

수업주: 3주차 / 2026.09.15~09.21

### 금주 예정작업

기존 계획과 실험 기록에서 해당 기간의 목표를 정리했다.

1. 병해 이미지 데이터와 클래스 구성을 점검한다.
2. 기존 ResNet50의 오류를 분석하고 추가 학습을 비교한다.
3. 학습·평가 자료의 중복과 원천 라벨을 확인한다.
4. LLM의 역할과 데이터 작성·검수 기준을 설계한다.

### 금주 수행결과

#### 1. 주요 수행 내용 및 팀원 개인별 수행 업무

| 수행 내용 | 결과 |
|---|---|
| 기존 모델 평가 | 축소 이미지 val 637장 중 613장 정답, 96.23% |
| 추가 학습 | 일반·역빈도 균형 샘플링 각 12 epoch 비교. 기존 모델을 넘지 못해 유지 |
| 원본·축소 이미지 비교 | 같은 모델에서 원본 603/637(94.66%), 축소본 613/637(96.23%) |
| 분할 중복 확인 | train–val 동일 이미지 2쌍, train–test 4쌍 발견 |
| 라벨 조사 | JSON 91,041개 분석, 현재 이미지 4,246장에 고유 라벨 연결 |
| 분할 후보 작성 | 작업자 기준 train 2,739 / val 785 / test 722 |
| LLM 설계 | 진단 설명·재촬영·정보 부족·후속 질문 등 시나리오와 근거·검수·분할 원칙 정리 |

확인된 개인 수행자는 김헌영이며, 모델 분석·데이터 감사·분할 설계·LLM 계획을 수행했다. 다른 팀원의 해당 주차 개별 완료 내역은 현재 근거 자료만으로 확정하지 않았다.

#### 2. 주요 문제점

- 평가 이미지 일부가 학습 자료와 중복되어 기존 지표의 독립성에 한계가 있었다.
- 기존 검증 오류 24건 중 무 두 병해 간 혼동이 13건으로 집중되었다.
- 확보한 정상 이미지 1,500장이 공식 Validation 출처여서 공식 분할만으로 정상 학습 자료를 구성하기 어려웠다.
- 추가 학습이나 원본 이미지 사용이 성능 향상을 보장하지 않았다.

#### 3. 해결 방법

- 이미지 해시와 원천 라벨을 대조하고, 작업자 단위로 분할을 다시 설계했다.
- 작업자 코드를 농장·개체 ID로 해석하지 않고 분할 독립성의 한계를 기록했다.
- 개선 조건을 충족하지 않은 모델은 채택하지 않았다.
- LLM 학습 자료는 실제 진단 결과와 검증된 DB를 근거로 작성하도록 계획했다.

### 다음주 예정작업

1. 중복 제거 후 작업자 분리 번들로 기준선을 학습·분석한다.
2. 같은 분할에서 224·256 입력을 비교한다.
3. 클래스별 재현율과 병해→정상 오류를 함께 분석한다.
4. 모델 출력·진단 이력·농약 정보의 신뢰성을 점검한다.

발표 요점: **3주차에는 정확도를 높였다는 주장보다, 기존 평가의 중복 문제를 찾아 비교 기준을 다시 마련한 점을 설명한다.**

## 2. 4주차 주간보고

수업주: 4주차 / 2026.09.22~09.28

### 금주 예정작업

1. 작업자 분리 ResNet50 기준선과 256 입력 후보를 비교한다.
2. 진단·재촬영·DB·이미지 업로드·농약 정보 처리를 개선한다.
3. 카메라 구현과 진단·이력을 연결해 검토한다.
4. 결과를 보고서와 기능별 리뷰 단위로 정리한다.

### 금주 수행결과

#### 1. 주요 수행 내용 및 팀원 개인별 수행 업무

**모델 실험**

후보 4,246장에서 학습 내 동일 바이트 중복 11장을 제거했다. 실제 번들은 **train 2,728 / val 785 / test 722, 총 4,235장**이다. 동일 작업자 분할·seed 42·batch 32·20 epoch에서 입력 크기 224와 256을 비교했다.

| 지표 | 224 기준선 | 256 후보 |
|---|---:|---:|
| 검증 정답 수 | 721/785 | 726/785 |
| 검증 정확도 | 91.85% | 92.48% |
| Macro F1 | 0.9035 | 0.9099 |
| 전체 오분류 | 64건 | 59건 |
| 병해→정상 오분류 | 29건 | 22건 |
| 무 두 병해 간 혼동 | 28건 | 31건 |

반올림 전 정답 수 기준 정확도 변화는 약 **+0.64%p**다. 256 후보는 기존 오류 17건을 맞히고 기존 정답 12건을 새로 틀렸다. 최종 test는 평가하지 않았고 서비스 모델도 교체하지 않았다.

**기록된 검증 결과**

- 9월 28일 백엔드: **183 passed, 1 skipped**. Windows 심볼릭 링크 권한 관련 항목 제외.
- 프론트엔드: 컴파일·타입 검사·페이지 생성 통과. 별도 작업 트리에서는 Windows junction에 따른 standalone 복사 경고가 있어 ARM64 배포 완료로 해석하지 않는다.
- 모델: 저장된 혼동행렬의 721/785·726/785 및 Macro F1 재계산 일치.
- 위 결과는 해당 날짜의 검증 기록이다. 이번 문서 작성에서 테스트나 학습을 재실행한 수치는 아니다.

#### 2. 주요 문제점

- 전체 정확도가 좋아져도 무 병해 간 구분은 악화되었다.
- 단일 seed 비교이며 작업자 분리가 농장·개체 독립성을 보장하지 않는다.
- 가상 카메라 연결은 확인했지만 미리보기와 저장 범위, 포커스·재생·캡처 실패 처리는 추가 검증이 필요하다.
- 로컬 구현·검증과 담당자 리뷰·병합·실기기 완료 상태가 다르다.
- LLM 학습과 보드·음성 통합 성능을 보고할 근거가 아직 없다.

#### 3. 해결 방법

- 256 모델을 후보로 보존하고, 새 오류와 무 병해 혼동을 원본·라벨 검토 대상으로 정리했다.
- 전체 정확도 외에 클래스별 재현율과 오류 유형을 함께 기록했다.
- 기능별로 변경을 나눠 선행 관계와 검증 근거를 남겼다.
- 카메라·보드·LLM 후속 작업에 별도 완료 조건을 설정했다.

### 다음주 예정작업

1. 무 병해 학습 자료의 촬영 조건을 검토하고 전문가 검수 자료를 준비한다.
2. 실제 휴대폰에서 촬영 범위·권한·실패 안내를 확인한다.
3. 배포 모델의 해시·전처리·클래스 순서·출력 규격을 통합한다.
4. 보드·패키지 준비 상태를 확인하고 CPU 추론 기준선을 측정한다.
5. 저장소 의존성 경고를 검토하고 조치 순서를 정한다.

발표 요점: **4주차에는 동일 조건의 모델 비교와 서비스 결과를 신뢰할 수 있게 만드는 개선을 수행했다.**

## 3. 5주차 중간보고

수업주: 5주차 / 2026.09.29~10.05. **실적 집계는 10월 1일까지**이며 주차 전체 완료 보고가 아니다.

### 금주 예정작업

4주차 후속 과제인 취약 데이터 검수·의존성 검토·서비스 실행 확인을 진행하고, 수행계획과 누적 실적을 발표 자료로 정리한다. 카메라·보드·LLM 작업은 담당자 확인과 준비 조건에 따라 이어간다.

### 금주 수행결과

#### 1. 주요 수행 내용 및 팀원 개인별 수행 업무

이번 자료는 김헌영의 작업 기록과 본 세션의 실행·문서화 기록을 정리한 것이다. 다른 팀원의 5주차 활동은 개별 근거를 받은 뒤 반영한다.

촬영면 임시 집계:

| 기존 라벨 | 앞면 추정 | 뒷면 추정 | 판단 불가 | 합계 |
|---|---:|---:|---:|---:|
| 무검은무늬병 | 53 | 263 | 28 | 344 |
| 무노균병 | 44 | 121 | 4 | 169 |
| 합계 | 97 | 384 | 32 | 513 |

현재 test 이미지는 열지 않았으며, 병해 라벨·학습 데이터·모델을 변경하지 않았다. 검수 대상 20장은 목적 표집이므로 라벨 오류율 추정에 사용할 수 없다.

#### 2. 주요 문제점

- 촬영면은 AI의 외형 추정이므로 전문가 정답으로 사용할 수 없다.
- 두 병해 모두 앞뒷면 사진이 있으므로 촬영면 부재만으로 오분류를 설명할 수 없다.
- 보안 검토는 9월 29일 스냅샷이며 현재 경고 상태나 수정 완료를 뜻하지 않는다.
- 10월 1일 HTTP 확인은 서버 실행·연결·모델 준비 상태 확인이다. 새 이미지 진단이나 브라우저 전체 동작을 재검증한 것은 아니다.

#### 3. 해결 방법

- 기존 라벨·모델 점수와 검수 양식을 분리해 전문가의 독립 관찰을 준비했다.
- 원본 해시와 manifest를 대조해 513장 목록·중복·태그 누락을 확인했다.
- 의존성 변경은 영향 경로와 호환 조합을 확인한 뒤 기능 검증을 동반하도록 후속 과제로 정리했다.
- 발표에서는 구현·검증·계획을 구분하고, 서로 다른 평가 조건의 정확도를 단순 추세로 제시하지 않는다.

| 카메라 실기기 검증 | 미리보기와 저장 범위, 방향·권한·실패 안내 확인 |
| 기능별 리뷰와 통합 | 계약 검토, 통합 후 테스트·화면 확인 기록 |
| 의존성 조치 | 호환 버전 적용 후 빌드·회귀 검증, 경고 재확인 |
| 모델 전달 계약과 보드 준비 | 모델 해시·입출력 규격, 환경·실제 추론 로그 |
| LLM 소규모 검수 세트 | 근거·누락값·불일치 상황에 대한 기대 응답 확보 |

발표 요점: **5주차 초반에는 취약 데이터의 원인을 단정하기보다 검수 자료를 준비하고, 실행 상태와 남은 검증 과제를 정리했다.**
