# Cropy UI/UX 디자인 주간보고서

- **작성일:** 2026년 10월 7일
- **보고 범위:** 현재까지 진행한 Cropy 모바일·데스크탑 UI/UX 디자인 및 Figma 문서화 작업
- **작업 도구:** Figma
- **작업 목적:** 모바일과 데스크탑의 디자인 일관성을 높이고, 주요 사용자 흐름과 예외 상황을 개발에 전달할 수 있는 형태로 정리

## 1. 주요 성과

기존 Cropy 화면을 바탕으로 배경과 마스코트를 활용한 모바일·데스크탑 디자인을 정리하였다. 스플래시 화면의 여러 시안을 제작하고, 촬영·분석·결과 저장·이력 조회 과정에서 필요한 안내 및 오류 상태를 추가하였다. 이후 디자인 시스템, 화면 패턴, 프로토타입을 최신 디자인 기준으로 정리하여 화면 설계와 개발 가이드를 함께 확인할 수 있도록 구성하였다.

| 작업 영역 | 주요 결과 |
| --- | --- |
| 모바일 디자인 | 공통 배경·마스코트 적용 및 섹션별 개발 가이드 정리 |
| 데스크탑 디자인 | 모바일과 동일한 시각적 방향으로 화면 확장 및 스플래시 제작 |
| 스플래시 | 로고·문구·구름·빛 표현을 조합한 여러 시안 제작 |
| 사용자 피드백 | 모바일 24종, 데스크탑 24종의 확인·완료·오류·로딩 상태 구성 |
| 컴포넌트 | 버튼·텍스트 정렬, 아이콘 규격 및 원본과 사용처의 일관성 정리 |
| 디자인 시스템 | 색상·서체·간격·라운드, 컨트롤·탐색·카드 상태 예시 추가 |
| 화면 패턴 | 모바일·데스크탑의 진단·이력·촬영 관련 상태 패턴 정리 |
| 프로토타입 | 주요 화면 전환과 피드백 상태를 연결한 검토용 흐름 구성 |

## 2. 세부 수행 내용

### 2.1 모바일 화면 리디자인 및 브랜드 에셋 적용

- 기존 모바일 화면의 섹션과 정보 구조를 기준으로 디자인을 정리하였다.
- 공통 배경 이미지를 활용하고, 화면 정보를 읽기 쉽도록 배경과 콘텐츠의 시각적 균형을 고려하였다.
- 마스코트를 화면 목적에 맞는 위치와 크기로 배치하여 브랜드 표현을 보완하였다.
- 마스코트가 본문, 버튼, 주요 정보를 방해하지 않도록 크기와 여백을 조절하였다.
- 화면 섹션별 오른쪽에 개발 가이드를 배치하여 디자인과 구현 기준을 함께 확인할 수 있도록 하였다.

### 2.2 스플래시 화면 시안 제작

- Cropy 로고와 프로젝트 소개 문구를 조합한 스플래시 화면을 제작하였다.
- 로고는 첫 글자를 대문자로 사용하는 **Cropy** 표기로 정리하고, 소개 문구의 크기와 비율을 조절하였다.
- Tropy Land와 tvN Enjoystories OTF를 활용하는 방향으로 로고·문구의 표현을 구성하였다.
- 구름 에셋을 배치하고, 개발 시 좌측에서 우측으로 반복 이동할 수 있도록 화면 구성을 고려하였다.
- 로고가 위에서 내려오는 동작과 문구가 한 글자씩 나타나는 동작을 고려한 디자인 및 가이드를 정리하였다.
- 벡터 빛줄기로 햇빛이 들어오는 표현을 추가하고, 각도·두께·개수·광원 위치를 달리한 시안을 제작하였다.
- Splash 04에는 얇은 빛줄기 2개, 중간 두께 1개, 굵은 빛줄기 1개를 조합한 방향을 반영하였다.
- 오른쪽 상단에 광원이 살짝 보이는 표현, 완성도를 중심으로 구성한 Splash 05, 아기자기하고 캐주얼한 Splash 06 등 대안을 제작하였다.
- 선택한 모바일 스플래시의 시각적 방향을 데스크탑 규격으로 확장하고 개발 가이드를 함께 추가하였다.

> 스플래시의 이동·등장·타이핑 동작은 디자인 의도와 개발 가이드로 정리한 내용이며, 실제 앱 애니메이션 구현은 후속 개발 범위이다.

### 2.3 데스크탑 화면 확장

- 제공된 데스크탑 규격을 기준으로 모바일과 동일한 색상, 배경, 마스코트 및 콘텐츠 표현을 적용하였다.
- 모바일 화면을 데스크탑의 넓은 공간에 맞춰 재구성하고, 콘텐츠 영역과 탐색 구조를 정리하였다.
- 마스코트의 크기와 위치를 데스크탑 정보 밀도에 맞춰 조정하였다.
- 모바일·데스크탑의 시각적 일관성을 유지하면서 각 환경에 필요한 레이아웃 규격을 구분하였다.
- 데스크탑 화면에도 섹션별 개발 가이드를 추가하였다.

### 2.4 모바일 사용자 피드백 및 예외 상태 설계

모바일 전체 흐름을 검토하여 사용자 확인이 필요한 상황, 작업 완료 안내, 오류 및 로딩 상태를 구분하였다. 입력 내용이나 결과가 사라질 수 있는 상황에는 확인 다이얼로그를 사용하고, 짧은 완료 안내에는 토스트를 사용하도록 구성하였다.

| 구분 | 추가한 상태 |
| --- | --- |
| 이탈·취소 확인 4종 | 사진 선택 후 이탈, 분석 중 이탈, 분석 취소, 저장하지 않은 결과에서 이탈 |
| 완료·안내 토스트 4종 | 저장 완료, 저장 재시도 성공, 분석 취소 완료, 음성 안내 사용 불가 |
| 사진·카메라 예외 6종 | 사진 형식 오류, 용량 초과, 사진 읽기 실패, 업로드 실패, 촬영 실패, 카메라 실행 중 오류 |
| 분석 예외 3종 | 네트워크 연결 불가, 분석 지연, 분석 시간 초과 |
| 저장·결과 예외 3종 | 저장 진행 중, 저장 실패, 결과 사진 표시 불가 |
| 이력·기록 예외 4종 | 이력 로딩, 이력 조회 실패, 기록 사용 불가, 기록 상세 조회 실패 |

- 총 **24종의 모바일 피드백 상태**와 재사용할 수 있는 원본 컴포넌트를 구성하였다.
- 상황별 문구, 버튼 역할 및 복귀·재시도 동작을 개발 가이드로 정리하였다.
- 기존 화면을 보존하면서 추가 상태를 별도로 구성하였다.

### 2.5 피드백 컴포넌트 V2 및 데스크탑 적용

- 기존 피드백 구성은 보존하고, 더 간결한 버튼과 여백을 적용한 V2를 추가하였다.
- 버튼이 하나인 경우 중앙에 배치하고, 안내 문구도 가운데 정렬로 통일하였다.
- 원형·삼각형 아이콘의 크기를 조정하고, 원본 컴포넌트와 사용 화면의 규격을 일치시켰다.
- 모바일 원형·삼각형 아이콘은 **64px**, 데스크탑은 **80px** 기준으로 정리하였다.
- 데스크탑에도 모바일과 동일한 **24종의 피드백 상태**를 구성하였다.
- 데스크탑 피드백 카드 폭은 **480px**, 피드백 버튼 높이는 **44px** 기준으로 정리하였다.

### 2.6 디자인 시스템 V2 정리

- 기존 디자인 시스템의 문서 구성 방식을 참고하여 최신 디자인 기준을 V2에 추가하였다.
- 현재 서비스의 **Cropy 그린 색상과 Pretendard**를 기준으로 공통 규칙을 정리하였다.
- 색상을 행동, 텍스트, 배경, 테두리 등 역할에 따라 사용할 수 있도록 의미 기반 변수로 구성하였다.
- 제목·본문·보조 문구 등 **10종의 V2 텍스트 스타일**을 추가하고 서체 예시에 연결하였다.
- 간격과 라운드 기준을 문서화하였다.
- 버튼의 기본·호버·눌림·비활성 상태와 토글, 필터, 배지, 탐색, 카드의 예시를 추가하였다.
- 실제 페이지에 사용하는 헤더, 하단 탐색, 버튼 등의 고정 셸을 별도 영역으로 정리하였다.
- 모바일 피드백, 데스크탑 피드백, 배경, 마스코트 및 사용 규칙을 종류별로 재배치하였다.
- 문서 영역을 기초 규칙, 컨트롤, 탐색·정보의 세 묶음으로 나누고, 섹션 간격과 규격 표기를 정리하였다.
- 기존 V2 컴포넌트 ID를 유지하여 화면 패턴과 프로토타입의 연결이 이어지도록 하였다.

| 피드백 아이콘 | 모바일 64px / 데스크탑 80px |

### 2.7 화면 패턴 및 프로토타입 최신화

- 모바일·데스크탑의 촬영, 진단 및 이력 관련 화면 패턴을 최신 디자인 기준으로 정리하였다.
- 모바일 이력 12종, 모바일 진단 5종, 데스크탑 진단 5종, 데스크탑 기록 5종, 데스크탑 이력 12종, 카메라 촬영 2종의 상태 패턴을 구성하였다.
- 프로토타입에는 모바일 기본 화면 23개, 데스크탑 기본 화면 24개, 피드백 화면 48개, 스플래시 2개, 시나리오 메뉴 2개를 포함하여 **총 99개 프레임**을 구성하였다.
- 사진 선택 → 분석 → 결과 확인 등 주요 흐름과 이탈·취소·저장·재시도 관련 피드백을 연결하였다.
- 모바일·데스크탑별 시나리오 메뉴를 추가하여 검토할 상태에 접근하기 쉽게 구성하였다.
- 새로운 흐름을 별도로 추가하고, 기존 프로토타입 흐름은 보존하였다.

## 3. 검토 및 확인 사항

- 디자인 시스템 문서에서 텍스트가 부모 프레임의 가로 영역을 벗어나지 않는지 확인하였다.
- 재배치한 각 영역이 지정한 디자인 시스템 섹션 안에 포함되는지 확인하였다.
- 모바일·데스크탑 피드백 원본 컴포넌트가 각각 24종 유지되는지 확인하였다.
- 프로토타입의 화면 이동 대상과 주요 촬영·분석·결과 흐름을 확인하였다.
- 요청된 영역 안에서 작업하고, 구버전과 기존 원본을 보존하는 방식으로 수정본을 관리하였다.

## 5. 기대 효과

- 모바일과 데스크탑에서 동일한 브랜드 인상과 UI 규칙을 제공할 수 있다.
- 작업 내용 손실, 분석 지연, 저장 실패 등 예외 상황에서 사용자가 다음 행동을 판단하기 쉬워진다.
- 반복 UI를 컴포넌트와 변수·스타일로 관리하여 화면 간 불일치를 줄일 수 있다.
- 개발자가 화면 규격, 상태별 동작 및 에셋 사용 기준을 함께 참고할 수 있다.
- 기존 시안과 최신 시안을 비교하고, 프로토타입을 통해 주요 사용자 흐름을 검토할 수 있다.

## 6. 후속 계획

- 최종 사용할 스플래시 시안을 선정하고 구름·로고·문구의 애니메이션을 구현한다.
- 디자인 시스템의 변수·스타일과 컴포넌트 규격을 프론트엔드에 반영한다.
- 사진 업로드, 분석, 저장 및 이력 조회의 실제 API 상태에 피드백 UI를 연결한다.
- 화면 크기에 따른 반응형 배치와 에셋 해상도를 실제 환경에서 검토한다.
- 키보드 조작, 다이얼로그 초점 이동, 토스트 표시 시간 등 구현 단계의 사용성을 확인한다.

## 7. 주간보고서 본문용 요약

이번 작업에서는 Cropy의 모바일·데스크탑 디자인을 동일한 브랜드 방향으로 정리하고, 공통 배경과 마스코트를 활용한 화면 및 스플래시 시안을 제작하였다. 촬영·분석·저장·이력 조회 과정에서 필요한 확인, 완료, 오류, 로딩 상태를 분석하여 모바일과 데스크탑에 각각 24종의 피드백 UI를 구성하였다. 버튼과 아이콘 규격을 통일하고, 색상·서체·간격 및 주요 컨트롤의 상태를 포함하는 디자인 시스템 V2를 정리하였다. 화면 패턴과 99개 프레임의 프로토타입을 최신화하고 섹션별 개발 가이드를 제공하여, 후속 구현에 필요한 디자인 기준과 사용자 흐름을 정리하였다.
