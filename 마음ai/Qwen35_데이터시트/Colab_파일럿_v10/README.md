# Qwen3.5 Colab 파일럿 v10 사용 안내

작성자: 김헌영  
작성일: 2026-10-08

현재 사람 승인 데이터는 0개입니다. 노트북은 승인 검사에서 중단하며, GPU 학습은 아직 실행하지 않았습니다. 이 단계는 기능 토큰의 등록·학습·저장 경로를 점검하는 소량 파일럿입니다.

## 1 사람 검수

1. `Cropy_Qwen35_사람검수표_v10.xlsx`의 A–C열만 읽고 D–I열에 독립 판정을 기록합니다. 기능 계약은 수정본의 `01_기능정의`, 반환·토큰 규약은 `06_토큰매핑`에서 확인합니다. 정답이 있는 대화데이터 시트와 별도 정답 CSV는 아직 열지 않습니다.
2. D에 기능명, E에 인자 JSON, F에 반환 상태, G에 예상 음성 안내를 작성합니다. H에는 실제 사람 이름, I에는 독립 검수일을 기록합니다. 작성 AI의 이름이나 자동 승인 기록을 넣지 않습니다.
3. 독립 판정이 끝난 뒤 `v10_사람검수_대조용정답.csv`를 열고 **case_id**로 대조합니다. J에는 대조일, K에는 최종 판정, L에는 근거와 수정 필요 내용을 적습니다.
4. 문장부호 없는 사용자 발화, 자연스러운 STT 변형, 의미 보존, 기능·인자·반환 상태, 근거의 충분성, TTS의 과장·누락 여부를 검수 매뉴얼대로 확인합니다. JSON·코드에는 문법에 필요한 문장부호를 유지합니다.

| 최종 판정 | 기준 | 학습 사용 |
|---|---|---|
| approved | 독립 판정과 현재 정답의 기능·인자·상태가 일치하고 근거·발화·TTS가 매뉴얼을 충족하며 실제 검수자·검수일·대조일·사유가 기록됨 | 포함 |
| reviewed | 대조했지만 의미가 모호하거나 확인할 사항이 남음 | 제외 |
| rejected | 잘못된 정답·의미 변형·근거 부족 등 불합격 사유 확인 | 제외 |
| 빈칸 | 사람 검수 미실시 | 제외 |

TTS는 문구의 완전 일치보다 의미와 근거를 확인합니다. 정답과 독립 판정이 다르면 정답 CSV만 수정하지 말고 원본 정답을 먼저 고친 뒤 검수표·정답 CSV를 새로 생성하여 재검수합니다. 정답 CSV는 원본 XLSX의 SHA256에 연결되어 원본 변경 시 기존 승인을 그대로 재사용할 수 없습니다.

검수표는 **129개**입니다. 신규 13개와 이전 보류 115개에, 검증 분할의 점수 조회 기능 사례 1개를 추가했습니다. 전체 2,800개에 대한 사람 검수 완료를 의미하지 않습니다. 최소 7개 기능 각각에 train·validation 승인 사례가 1개 이상 있어야 파일럿을 시작합니다. 기존 분할은 유지합니다.

## 2 Drive 업로드 및 실행

다음 구조로 업로드합니다.

```text
MyDrive/cropy_qwen_v10/
  Cropy_Qwen35_복합요청정리_v10.xlsx
  Cropy_Qwen35_사람검수표_v10.xlsx
  v10_사람검수_대조용정답.csv
  Colab_파일럿_v10/
    Cropy_Qwen35_기능토큰_파일럿_v10.ipynb
    cropy_qwen_pilot.py
```

1. 노트북을 Colab에서 열고 GPU 런타임을 선택합니다. 첫 설정 셀의 파일 경로와 모델을 확인합니다. 기본 모델 후보는 `Qwen/Qwen3.5-2B`입니다.
2. Drive 연결과 데이터 승인 검사부터 실행합니다. 승인 0개, 검수 누락, 정답 불일치, 원본 해시 불일치 또는 분할 교차가 있으면 원인을 정리한 뒤 다시 실행합니다.
3. 사람 승인과 설정 확인 후 `RUN_MODEL_STEPS=True`로 바꾸고 처음부터 실행합니다. 패키지 설치 후 재시작이 필요하면 런타임을 재시작하고 다시 실행합니다.
4. `OUTPUT_DIR`은 새 폴더여야 합니다. 재실행 실험에는 `pilot_outputs_v10_run2`처럼 새 경로를 지정합니다.
5. 토큰·마스킹·gradient 검사를 통과하면 20 step 파일럿이 진행됩니다. 기능당 최대 train 16개, validation 4개이며 실제 승인된 수량만 사용합니다.
6. 결과의 `train_metrics.json`, `eval_metrics.json`, `eval_cases.json`, `reload_check.json`을 확인합니다. 함수·인자·출력 형식·종료 토큰·완전 일치와 기능별 성능을 비교합니다. 재로딩 대조가 실패하면 해당 파일럿을 배포용으로 사용하지 않습니다.

## 3 노트북에서 점검하는 항목

- 현재 원본·검수 입력·대조 정답 연결과 실제 사람 승인 여부
- 49개 기능·인자·종료 토큰의 고유 ID, 단일 토큰 인코딩, 정확한 왕복 변환
- 입력 프롬프트의 loss 제외와 정답 토큰만 학습, 길이 초과 시 중단
- 텍스트 영역 LoRA 및 새 토큰 가중치의 gradient 확인
- 허용된 단일 함수와 enum 출력 검증, 잘못된 출력은 실행하지 않음
- 모델 commit, 실제 패키지·GPU·수량 기록, 어댑터·토크나이저 저장 및 재로딩 출력 대조

양자화 시 토큰 ID를 미리 하드코딩하지 않습니다. 이 실행에서 생성한 토큰 매핑을 저장하고 재로딩 때 비교합니다. 여기의 4bit 로딩은 Colab 메모리 절감을 위한 것이며 보드용 양자화·내보내기를 완료한 것이 아닙니다. 실제 handler 호출과 TTS 음성 출력도 별도 연동 작업입니다.

## 4 현재 확인 범위

로컬에서는 승인·출력 파싱·마스킹 관련 12개 테스트, 실제 파일의 승인 0개 차단, 129개 검수표의 빈 승인 필드와 원본 해시, 노트북 Python 구문을 확인했습니다. Colab GPU에서 모델 다운로드·역전파·학습·저장 후 재로딩은 아직 실행하지 않았습니다. 설치할 라이브러리 조합과 GPU 메모리 적합성은 첫 실행 결과로 확인해야 합니다.

복합 요청 2개를 clarify_request로 변경하여 현재 기능 수량은 clarify_request 402개, get_recapture_guidance 398개이며 다른 5개 기능은 400개입니다. 전체 train 2,240개와 validation 560개는 유지됩니다. 본학습 전 기능당 400개 목표를 다시 맞출 경우 원문 가족 단위 분할을 보존하고 검수표·대조 정답도 갱신합니다.
