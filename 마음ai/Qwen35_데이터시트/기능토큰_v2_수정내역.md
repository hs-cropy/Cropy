# 기능 토큰 데이터시트 v2 수정내역

작성자 김헌영 · 2026년 10월 6일

검수 결과와 기능 description 기반 학습 요구사항을 반영한 파일럿 초안이다. 기존 v1 파일은 보존했다.

| 항목 | 반영 결과 |
| --- | --- |
| 기능 정의 | 7개 기능의 설명 파라미터 enum 반환 상태와 payload 설계 |
| LLM 정답 | 기능 토큰과 인자 토큰을 연결하고 `<hs-end>`로 종료 |
| 음성 답변 | 기존 답변을 TTS 참고 예시로 보존하고 반환 상태별 템플릿을 별도 시트에 작성 |
| 현재 학습 대상 | 싱글턴 120개 초안 학습 96개 검증 24개 |
| 후속 단계 | 기존 멀티턴 40개 대화 80개 턴은 보류 |
| 발화 보강 | 합성 STT 및 사투리 변형 40개 추가 원본과 동일 그룹 및 분할 유지 |
| 입력 검증 | 모델 입력 문장부호 0개 동일 발화 0개 그룹 분할 충돌 0개 |
| 자료 보존 | 기존 근거 130개와 변경 전 입력 보존 |
| 자동 검증 | 204개 행의 함수 인자 토큰 종료 및 TTS 키 연결 확인 수식 오류 0개 |
| 검수 상태 | 작성자 김헌영 모든 데이터 draft 검수자 및 검수일 미기입 |

싱글턴 120개만 집계하면 8대2다. 보류된 멀티턴까지 합친 160개를 현재 학습 수량으로 사용하지 않는다. 같은 시드의 변형은 같은 split을 유지한다. 분할을 맞추기 위해 기존 두 그룹 전체를 validation으로 이동했다.

기능당 400개는 목표이며 아직 달성하지 않았다. 각 기능의 목표는 학습 320개 검증 80개이며 전체 목표는 2800개다. 승인 수량은 0개다. 엑셀의 초안 수량과 승인 기준 부족량을 구분했다.

토큰 문자열은 49개지만 실제 tokenizer 등록과 단일 token ID 검증은 하지 않았다. `<hs-end>`와 모델 원래 EOS는 별도로 설정해야 한다. 양자화 산출물의 tokenizer와 ID까지 확인한 뒤 고정 매핑을 사용한다.

STT 사례는 모두 합성이다. 실제 음성 로그가 아니며 원래 의미와 인식 오류 발화의 의미가 유지되는지 사람 검수가 필요하다. 특히 숫자와 모호한 병명은 컨텍스트에 근거가 없으면 확인 질문으로 처리해야 한다.

기능 handler와 TTS 템플릿은 설계 초안이며 구현이나 실행 완료가 아니다. 사용 전 템플릿에 없는 조합을 보완하고 반환 필드의 존재 및 검증 상태를 확인해야 한다. 실제 학습과 모델 평가는 수행하지 않았으며 평가 24개는 not_run 상태다.
