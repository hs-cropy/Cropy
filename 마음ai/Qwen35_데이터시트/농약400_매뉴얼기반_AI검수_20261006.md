## 확인된 결함과 보류 사유

행별 상세 표의 코드로 필터링하여 수정한다. 불합격을 수정한 뒤 해당 원문 가족의 STT·사투리, 정답 토큰, 평가 정답과 TTS를 함께 재검수해야 한다.

- ARG_PRODUCT: 빈 제품 목록에 current 지정. 목록 요청은 all로 수정하되 예방 필요 여부와 사용법 의도는 별도로 재판정한다.
- TTS_MAPPING: 동기화 시각 질문에 시각 부재를 직접 답하지 않는다. 미검증이라는 사실만으로 날짜 질문에 답한 것으로 처리하지 않는다.
- RETURN_STATUS: 실제 등록 여부 조회와 미검증 상태 조회를 구분해야 한다. 등록 여부를 확인할 근거가 없으면 정보 부족이다.
- 보류: 정상 결과와 병해 컨텍스트의 불일치 가능성, 어색한 문장·사투리, 부분 요약의 반환 계약을 확인해야 한다.

## 데이터 전체의 한계와 학습 전 남은 일

- 신규 377개는 원문 가족 138개에 STT·사투리 변형을 추가한 합성 자료다. 400개의 독립 상황이나 실제 STT 녹음으로 해석하면 안 된다.
- 신규 실제 사용 조건·성분·비교·혼용 사례에는 확인 값이 없어 정보 부족 응답 위주다. 검증된 값이 있는 성공 사례, 모호한 제품의 확인 요청, 부정어·수량·단위 인식 오류를 별도 기능과 함께 보강해야 한다.
- 신규 발화의 현재 표시된 제품과 반복 어미가 많다. 형식적 중복 0건이 충분한 현장 발화 다양성을 보장하지 않는다.
- P_P007은 시각 부재를 명시하며 ok로 되어 있다. 시각 자체 요청과 시각 존재 여부 조회의 상태 기준을 문서화하여 신규 시각 질문과 일관되게 맞춰야 한다.
- 토큰 ID 등록, tokenizer 고정, 양자화 후 ID 매핑과 종료 동작, handler 반환값과 TTS placeholder 채움, 실제 음성 재생·모델 평가를 이번 검수로 완료한 것은 아니다.
- AI 검수 통과 행도 사람 검수 전이다. 불합격·보류 제거 후 자동으로 320대80을 유지한다고 가정하지 말고 원문 가족 단위로 재구성한다.
