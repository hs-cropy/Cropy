## 검수 방식과 판정의 한계

- 저장된 v5를 직접 추출해 전 행의 ID 문장부호 JSON 인자 enum 토큰 순서와 종료 연결 분할 평가/STT 동기화 수식 오류를 검사했다.
- 신규 6개 기능은 발화 유형과 합성 컨텍스트 구성 및 답변 규칙을 대조하고 행별로 같은 결함의 적용 여부를 검사했다. 반복 변형은 가족 단위로 검토했다. 농약 400개는 이전 개별 AI 검수의 사용자 입력 정답 답변 컨텍스트가 동일함을 확인하여 판정을 승계했다.
- 작성 때 정답과 원문을 이미 보았기 때문에 매뉴얼의 독립 블라인드 사람 검수를 충족한 것으로 표시하지 않는다. 문제 미발견도 approved가 아니라 reviewed다. 독립 검수자는 user_text와 필요한 context만 먼저 보고 기능과 인자를 결정한 후 정답과 비교해야 한다.
- 합성 STT는 실제 녹음 검증이 아니며 실제 tokenizer ID 등록 모델 학습 기능 실행 TTS 합성 검증도 하지 않았다. 형식 통과가 학습 허가를 뜻하지 않는다.

## 수정 및 재검수 순서

1. 불합격의 기능/인자와 TTS 필수값 불일치를 먼저 수정한다. 입력·토큰·반환 상태·TTS·평가·STT 관련 열을 함께 동기화한다.
2. 보류된 반환 경계와 한국어 TTS 및 STT 변형을 확정한다. 원문 가족 전체에 같은 정책을 적용한다.
3. 변경 행은 draft로 되돌려 재검수한다. approved를 임의로 채우지 않는다.
4. 독립 검수 후 승인된 대화만 집계해 기능별 320/80 결손을 보충한다. 현재 승인 대상 export는 0개다.
5. 실제 tokenizer 종료 동작과 handler/TTS 작은 실험을 확인한 뒤 Colab 학습을 진행한다.
