## 실제 오답

정답은 함수 토큰과 인자 토큰 뒤에 종료 토큰이 오는 구조입니다. 이번 실제 출력은 모든 사례에서 종료 토큰 하나뿐이었습니다.

```text
정답 예시: <hs_clarify_request><hs_target_stt><hs-end>
실제 출력: <hs-end>
```

저장된 출력 ID 248125를 token_manifest.json 및 저장된 tokenizer.json과 대조하여 hs-end임을 확인했습니다. 각 사례의 정답은 실행 원본 XLSX에서 읽어 평가 지표를 다시 계산했으며 저장된 0% / 100% 수치와 일치했습니다.

## 확인한 동작

- 원본 XLSX SHA256과 system 프롬프트 SHA256이 실행 기록과 일치
- 학습 112개·검증 28개의 ID와 split이 일치하고 ID 교차 없음
- 각 기능에 학습 16개·검증 4개가 포함됨
- 49개 토큰 ID와 저장된 토크나이저 매핑이 일치
- 20 step의 loss·gradient norm 기록에 NaN이나 무한대 없음
- 저장된 어댑터에 49×2048 새 토큰 가중치와 LoRA 가중치가 있으며 모두 유한함
- LoRA B 가중치가 모두 0인 상태는 아님
- reload_check.json에 토큰 ID 일치 및 검증 28개 greedy 출력 일치가 기록됨

재로딩 기록의 의미는 저장 전과 저장 후 출력이 같다는 것입니다. 잘못된 hs-end 단독 출력도 그대로 유지됐으므로 정답 성능을 보증하지 않습니다. 로컬에서 GPU 모델을 다시 불러 재로딩을 재실행하지는 않았습니다.

## 해석과 다음 실험

loss는 감소했고 가중치가 저장됐지만, 자유 생성에서는 함수·인자보다 즉시 종료하는 출력이 우세합니다. 20 step은 약 0.71 epoch에 해당합니다. 학습량 부족 가능성을 검토할 수 있지만 현재 로그만으로 부족한 step이 유일한 원인이라고 단정할 수 없습니다. 학습 사례에 대한 생성 결과와 위치별 정답 확률이 없어, 학습 데이터에서도 동일하게 종료하는지는 아직 확인하지 못했습니다.

다음은 같은 학습 112개·검증 28개와 모델·seed를 유지하고, **학습 사례의 생성 결과도 평가**하는 실험이 적절합니다. 100 step 정도의 비교 실험에서 함수·인자·전체 출력 일치와 hs-end 단독 출력 비율을 확인하세요. 학습 사례에서도 종료 토큰만 출력하면 loss 마스킹, 추가 토큰 및 출력 가중치 연결, 정답 첫 토큰 확률을 점검합니다. 학습 사례는 맞추는데 검증만 실패하면 일반화와 데이터 구성을 점검합니다. 강제로 종료 토큰을 막는 방법은 자연 생성 성능과 별도 지표로 구분해야 합니다.

이 실험은 사람 검수되지 않은 초안 정답을 사용했습니다. 실제 서비스 정답 품질이나 STT 음성 성능을 검증한 결과는 아닙니다.
